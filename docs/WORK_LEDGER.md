# Koma 工作台账（WORK LEDGER）

**持久化工作机制：本文件提交在仓库里，压缩/换会话后依然存在。每个工作会话开始时先读本文件再动手；每完成一项就地勾选并写提交哈希；用户新输入一律追加进队列，不允许冲掉已有条目。**

## 工作协议

1. 先读队列与黑名单再动手；进行中的切片必须做到独立提交边界才切换（用户明确说优先/停止除外）。
2. UI/交互存在 NextE 参考时，先读参考实现完整段落再移植；写完与参考逐条对照。
3. 验收清单在动手前写进切片记录；完成后在 197 截图 + dump 数值逐项对照（贴边/遮挡/首行完整/按钮形态/间距）。
4. 未验证/未确认的产物禁用成功语言；只陈述证据。
5. 断言平台能力前先查已验收协议/离线文档/参考仓库；查不到就明说未查到。
6. 用户报告新问题：先入队再执行，不允许静默丢弃或只回应最后一两条。

## 失败模式黑名单（已发生，禁止重演）

- 自创功能：无用户需求、无对标缺口分析，看到参考组件就移植（案例：页码跳转——Koma 同章已有滑动条，功能冗余、入口不可发现，已整体回退）。
- 验收自我循环：只验证功能通不通，不验证呈现（案例：搜索框遮挡首行封面、页码跳转键盘盖按钮，均宣布过完成）。
- 对未验证产物使用成功语言（案例：「完美弹出」）。
- 用户新输入冲掉进行中工作；只回应最后一条，其余无视。
- 未查证断言平台能力（案例：断言无旋转调试命令）。
- 约束只写在对话里，压缩后消失（本文件即对策）。
