# Koma 跨设备同步设计

用户本会话已明确要求重做整套同步界面。旧界面整体通过结论已撤回；下述页面方案已完成独立设计与反方复审，候选已接入真实目的地及独立配置事务，正在做实现复审与真机验收，尚无新版UI通过结论。用户本会话已明确采用「保存配置与开始同步分开」及更换空间保存成功即停旧连接的提交点。既有数据、隐私与失败恢复边界继续有效。开发与验收进度见[当前工作单](../../CURRENT_STATUS.md)。

## 用户能带到另一台设备上的东西

首版提供五组数据。同步在用户连接、核对范围并确认首次合并后才启用。

| 分组 | 同步内容 | 首次连接默认 |
| --- | --- | --- |
| 书架与分类 | 已收藏的可识别公开书源作品、手动分类的名称和顺序、作品所属分类。增删和移动都能传递。 | 选中 |
| 阅读记录 | 可识别公开书源作品的历史、最近阅读章节和页码、逐章阅读位置、已读/未读、章节书签。即使未收藏也能续读。 | 选中 |
| 阅读偏好 | 全局阅读方向和模式、翻页动画、页码显示、图像适配。按书只同步阅读方向和模式，限可识别公开书源作品。 | 不选 |
| 书源订阅 | 共享经过验证的公开目录订阅及名称。设备各自控制实际地址、启停和最近使用顺序。收到的目录可由用户选择加入。 | 不选 |
| 搜索历史 | 实际只查询经确认公开书源的普通搜索词原文。界面仍显示最近 20 条，混合范围、私库、本地和其他限定查询留在本机。 | 不选 |

首版「书架与分类」「阅读记录」均在说明里写明适用于能安全跨设备识别的公开书源作品。无法证实为公开域的账户/私有会话作品暂留本机，首次预览显示跳过数量和原因。书架上现有私库和本地作品及其分类成员关系保留；同步分类删除若仍含本机作品、局部展示策略或智能分类依赖，保留原本机分类 ID、设备成员、视图设置和依赖。断开共享身份，作为本机分类保留，不自动重新上传。收到的取消收藏若关联本机笔记或封面，先显示本机待处理项，用户可确认移出或主动重新收藏。在处理前不会清理本机笔记或图片，也不会把该本机占位当成一次新收藏。内置分类按固定身份识别，只有用户成员关系参与。手动分类名属于用户数据。选中这组会共享手动分类名，即使分类为空或只含本机/私库作品，实际作品和私有成员关系仍留在本机。首次合并前列出分类名并明确提示后续新建、改名也会同步。分类暂时变空不视为删除。

笔记、封面、统计、远程私库和本地文件列入完整方案的后续能力。分别需要并发笔记保全、受校验的资产传输、真实会话的持久唯一身份、服务和账户配对、同一内容的显式配对。实施这些能力前要单独评审范围和界面。本机下载、权限、第三方授权、私有订阅和设备操作偏好有明确保留边界。

## 设置结构与用户路径

本节取代旧界面的同页管理/编辑/预览结构。重开依据是用户本会话明确指出「编辑连接」没有路由动画，并要求「重头设计这一整套界面」。被否定的旧实现仅切换 `editing`、`preview` 并替换正文，测试还会进入预览或恢复未决真实提交；本候选已拆为真实目的地与纯探针。旧实现及旧评审不能作为这些行为应被保留的依据。

实查 NextE 和 NextN：同步总览与 WebDAV 设置使用两个真实导航目的页；WebDAV 页固定展示服务操作与连接字段，没有点击编辑后原地换页。两参考字段变化时保存配置，离页再 flush。Koma 保留明确取消和失败不替换旧连接的边界，因此采用显式保存；首次合并核对也是 Koma 既有数据安全需求。增加两个目的页是为这两项独立事务适配，不能冒称参考本身就有四页。

入口仍为「设置 → 备份 → 同步」。不在设置根页新增分类，不改现有备份创建、恢复及文件操作。备份副标题、同步入口与设置搜索继续沿现有落点；「同步」到服务列表，「WebDAV 同步」到服务管理。普通入口逐级返回并保留滚动位置，搜索入口回原查询；平板沿宿主现有设置导航容器，不自行创造另一套分栏。

### 四类真实目的页

| 页面 | 负责什么 | 具体内容与动作 |
| --- | --- | --- |
| 同步 | 选择同步服务 | 当前只有 WebDAV 同步一行，显示未配置、待首次核对、已关闭、仅手动、上次成功或需处理等准确摘要。未来服务同级加入，当前不放不可用入口，也不设置全局总开关。 |
| WebDAV 同步 | 日常管理当前服务 | 服务组：独立启用、自动同步、立即同步。连接组：配置/编辑连接。同步内容组：原五组范围。存在待处理时显示具名入口。状态组：当前结果与上次成功分开。末组：断开连接。 |
| 配置连接／编辑连接 | 一次配置事务 | 地址、用户名、密码；标题栏「保存」，字段下「测试连接」。测试只测试；返回丢未保存草稿，成功保存后原生返回管理页。 |
| 核对合并 | 一次有明确影响的数据事务 | 首次、新空间、范围扩展、恢复或待处理差异分别使用准确标题。展示影响摘要、具体删除和两侧值、当前选择、跳过与保留原因。有效合并计划才有标题栏「确认合并」。 |

四页均由宿主注册真实 HDS 导航目的地，使用公共标题、分组、表单和材质；管理页不以布尔值替换整页来冒充编辑/核对。箭头行确实 push；进入与返回有原生转场。普通手动同步留在管理页，不强迫经过编辑或核对。范围留在服务管理内，不再加范围页、状态中心或配置向导。

### 配置：测试、保存和开始各有结果

- 测试连接为可选诊断，只验证当前三字段的认证、目录和本机专属探针写读清理。事前说明会创建并清理临时对象；只清自己的精确路径，中断保留清理债务。测试不保存、不读真实同步分片、不恢复未决提交、不生成合并计划、不启用服务。任一字段改变立即使原测试结果失效。
- 保存先校验，必要时执行同样的纯探针，之后原子保存。表单说明「保存时验证连接，不同步数据」，过程中显示「正在验证并保存」；同一草稿的有效探针结果可复用，不要求先点一次测试。零范围或服务关闭时也能保存。验证或安全资产保存失败留在表单，旧服务保持有效，不能先停旧服务再验证。
- 编辑返回和系统返回都丢未保存草稿。迟到测试/保存结果不得复活已退出的页面、覆盖管理页错误或提交已放弃输入。原连接的自动策略和最后成功不被草稿错误改写。
- 同地址、账户仅修改口令，保存成功保留已授权空间、原范围、待传意图、启停和自动策略；原来关闭就仍关闭。测试不替正常同步的真实空间校验。地址、账户或目录改变视为新的配置事务，旧空间意图隔离保留，不自动投向新目录。

**用户本会话已明确采用的配置提交点：** 配置可以独立保存为「已配置 · 待首次核对／待核对新连接」。首次或更换地址/账户/目录保存成功后，新服务尚不收发；更换已有端点时，旧服务在这次保存成功的提交点停止。核对取消仍保留已保存的新配置且不运行。旧实现是确认合并后才替换有效连接；本方案把停止旧连接的时点提前到成功保存。保存前明确提示这一影响；取消编辑或保存失败继续保留旧服务。采用依据为本会话对该具体行为问题的明确答复「采用：保存配置与开始同步分开」；不得扩大为变更其他数据合同。

### 启停、自动与范围

- 每种服务独立保存启用状态、凭据、范围、游标、队列和调度。WebDAV 关闭保留这些本机资料及原始阅读 capture，停止真实数据收发、手动同步和前台网络恢复；自动开关保留原值并置灰。关闭不是断开，不删两端内容。未来新服务不得覆盖 WebDAV 的信号监听或使用全局启用布尔值。
- 首次保存后为待核对，启用开关与「核对并开始同步」走同一真实核对路径；确认前开关仍为关闭，只给本次核对所需的临时读取许可，不提前持久启用后台收发。取消撤销该次许可，保存配置保留。确认才启用并执行精确计划，首次自动仍关闭。已完成首次核对的连接暂停重开沿原范围和原自动策略恢复；备份恢复、新空间等未授权状态不能借重开绕过核对。
- 自动仅控制触发。已启用而自动关闭时，用户可立即同步；服务关闭则不能手动发数据。日常自动合并沿事实版本规则，不能每次都弹首次核对，也不按错误设备时间覆盖更近的因果事实。
- 原五组和默认不变：书架与分类、阅读记录默认选中；阅读偏好、书源订阅、搜索历史默认不选。含义见本文首表，不能因页面重做扩大隐私范围。原总览的组移入当前服务，不能让它看似控制所有未来服务。
- 关闭某组立即停收停发，不清两端已有数据或此前获准意图，关闭期间不采集该组同步操作。新开组确认前不生效：服务已开时进入核对，取消恢复原范围；服务关闭时只允许本页临时新增草稿并标记待核对，不联网，离开丢草稿。重开先恢复旧授权范围，新增组仍要显式核对。全部关闭说明「尚未选择同步内容」，不创建空任务。
- 服务暂停使传输代次与迟到回调失效，逐次实际请求前检查；不跳过本机事务完成或回滚、启动纯本地恢复。暂停期间原已选组的真实本机删除、清空、未读仍按原观察版本记录；同步用途的公开源检查只用缓存，用户主动阅读和验证不受影响。
- 断开使用公共确认 Dialog，说明「删除本机连接凭据，服务器数据保留」。同时撤除本服务探针凭据；安全资产删除失败保留待清理引用重试，不再拿旧凭据联网。结果未知的旧空间提交隔离保留，只有重新授权同空间才核对，迟到结果不能写新连接。

### 核对、取消与异常

- 进入核对显示本次原因和安全目录摘要，上传、接收、删除、暂缓、跳过按组分开；列出具体将删条目、冲突的两侧实际值和当前选择，用原生菜单逐项选。作品、章节和页码足够辨认；远端可能汇总多设备，称「本机／同步数据」，不笼统冒称「另一台设备」。分类名共享、公开源边界与跳过原因在确有影响时说明。
- 存在有效精确合并计划才显示「确认合并」。只处理收到订阅、带本机笔记/封面的移出书架、阅读冲突或保留 capture 时，沿各自明确动作，不挂一个没有可提交计划的万能确认；所有原能力保留，不能用总数字掩盖入口。
- 返回丢本次预览和选择、回发起它的管理页；已保存连接保留，新增范围未确认不生效。预览绑定不可变分支、连接版本、选择、本机 owner 修订与完整影响；发现变化需重新核对，只提交眼前精确计划，不扩大到迟到新分支。
- 无共同基线的不同值默认暂缓并保留双方，该项及依赖不改两端，其余无冲突项仍可合并并自动继续。删除冲突不默认复活，只有明确重新收藏、恢复书签或采用本机位置才产生重建。恢复等连接级重新授权才阻塞整服务。
- 测试失败、配置保存失败、同步失败、远端结果未知、本机待恢复分别显示；保留最后成功时间，不能将新草稿错误写成旧连接失败。需要时显示「核对上次同步」处理原精确意图，测试不承担它。凭据、目录/父目录不存在、无权限、空间满、重定向、本地写入、清单损坏或版本过新各给对应可行动原因；不强制条件写、ETag 或 LOCK。
- 已见提交或祖先缺失暂停读写，目录漏列先直接核已见路径；未知不能视为删除。恢复旧快照须明确确认新空间和合并，不跨空间重放队列。全新设备只报告当前能验证的空间和影响。
- 拉回条目从原书架/历史续读。缺源保留书名、源名、精确源 ID、章节和页码，沿已有查找/启用/更新/章节列表/重试路径。按精确身份查已配置目录，区分无匹配、不可用、停用；不近似配对、不按远端 URL 自动安装。取消或失败保留原位置，回原条目，装好由用户续读，不跳到第 1 页假装成功。

## 记录身份、合并与删除

发行原始清单和正常备份生成的宿主清单分别使用已核的固定长度与摘要，实际运行的 WASM 另行核验。普通备份恢复后的包保留同步能力。已安装并启用但未通过校验时，说明本机包尚未核验并保留原章页，提供查看版本和导入匹配发行包的入口。

- 书源作品键是结构化的「来源类型、经确认的包身份、原始作品 ID」，章节再加原始章节 ID。可同步合同按已审查的目录发行身份及支持版本列出稳定 ID 语法、页位能力和无账号访问能力。包自报公开、包名相同、已装目录地址和标题都不能证明作品是公开的。本地导入时，包清单与实际运行字节同时匹配已核的官方发行资产，可以补足没有登记目录来源的安装。发端要求本机有包版本及具体作品的匿名访问来源证据。Host 验证上下文拒绝授权头、Cookie、私有 RPC、认证重定向和携带凭据的 URL、请求体或设置，不写普通会话或观测缓存。旧记录只从可证来源或在预览中按需验证补齐。接收端离线校验协议字段、发行身份和标识语法，不执行源。合同已知但源未安装时生成不可打开的待解析条目，用户从正常路径安装/查阅时再验证。合同未知的记录隔离并在同空间保持原字节，不能当作本机数据再上传或跨空间迁移。发送和接收使用独立字段表，作品和章键受源专属语法约束，仅显示有界普通文本、源可辨名称和安全元数据。现有 `Comic`、历史 DTO、原始/签名 URL、绝对路径、账户态和网络响应不直接序列化。首版合同验证从源码已核候选开始，包括 MangaDex `org.mangadex.koma` 0.1.25（作品 `mdx:<UUID>`、章节 `ch:<UUID>`）、xkcd（中文）`com.xkcd.zh.koma` 0.1.7（`xkcd:zh`、`xkcdch:zh:<正整数>`，分组版含数字组码）。MangaDex 多页、xkcd 缺源回流分别真机验收。其他源逐个按同一合同加入，并显示当前支持及跳过范围；候选源码版本不表示已通过发行来源和真机验证。
- 续读按作品保存章键和最近一次实际进入该章的选择，页位按章节保存原始逻辑页、当时页数和可验证的稳定页标识。按现有意图区分预载、普通详情、恢复已有位置和实际阅读。读取回填、页面载入、退场时的重复保存不产生新编辑。两端确认同一页表才可用逻辑页序回退。Host 按页序补的 ID 不是源提供的稳定 ID，同章同页数也不足以证明页表一致。保留来源声明及可验证页表指纹，验同页数重排、不同源设置和合成 ID；设备本地分栏不进页位记录。页标识失配、页数变化或章不再可用时保留远端章页，提示打开目录或重新定位。已选章继续从该章当前合并页位读取，真实重读允许向前。
- 每次用户动作得到 `(replicaId, seq)`，同一副本持久单调递增。每个事实寄存器保存候选版本、已观察的每副本序号向量及变更种类。普通操作在动作产生时捕获该事实的向量，导入与回写沿用原版本；会话内迟到的结果只能携带原动作向量。合并按向量偏序移除被因果覆盖的候选，重复同一版本幂等。并发时保留仍在前沿的候选。同键显式删除、取消和未读重置作为独立屏障集合保留，即使有效新值覆盖了旧可见值也不清屏障。正值必须观察该键全部有效屏障才能投影；后继屏障可吸收已观察的旧屏障。批量清除另存每键的已见序号向量，只隐藏被向量覆盖的旧值，不能压过未观察到的同键新事件。同类型候选以协议固定的副本 ID 顺序、同副本序号顺序投影；因果明确时后继版本优先。设备 UTC 仅用于展示，不决定胜负。用户可在本次同步结果查看同一作品并发的两个续读位置，选择另一位置是一次观察了双方的新动作。
- 收藏、分类名称/顺序、成员边、续读选章、逐章页位、已读、书签、各偏好项各有独立版本。标记未读为带同一动作 ID 的原子操作，写已读为否，并对该章写第 1 页重置，当前续读指向该章时随页位显示第 1 页；它不改指向另一章的续读，也保留书签。另一个副本尚未见重置的同章页位更新不能盖过重置。单章书签取消为明确删除，书签与阅读事实并发都生效。批量动作的成员以用户实际选择的章节为准。同一章并发「已读/读完」与「标记未读」保留未读及归零。观察过未读后的真实读完重新标已读。仅点「标记已读」不改变已有页位。
- 删除历史只移除历史及续读选章。保留各章数据、书签、已读和接收设备已有的本机统计。发起设备保持现有行为，另清该书的本机统计。确认文案说明两端影响。收藏造成临时历史行去重不当作用户删除。清空历史为本机实际可见的历史逐键记录删除及已见版本，保留从未看到的另一端独立记录。清空搜索覆盖范围由下一条定义。同步中的删除及重置对发起时尚未观察它的本机活跃 Reader 会话形成屏障，照常阅读，迟到和退场保存不能把远端刚删除的历史或重置前页位写回；用户在下一次显式打开或从冲突中确认后才生成观察到屏障的新位置。被挡的位置保留为本机可恢复候选，本次结果说明。
- 搜索历史保留独立同步记录和删除信息，本机 owner 仍只投影最近 20 条，保留目标端原有限定查询。现有「全部」同时查私库、本地和书源，「书源」也可能包含账户源。首版仅分享实际搜索计划能证明每个目标均为受支持公开书源、无私有会话的普通查询。旧查询没有这份证据，只保留本机。收到记录按同一公开范围的可用源交集重放，无可用目标时只填词并提示，不回落到「全部」。混合范围、限定库和高级语法留本机。保留本机限定词的持久副本，不因同步投影而永久挤出。稳定键是协议固定版本的 NFC、折叠空格、Unicode 默认大小写折叠及范围枚举，禁止用系统语言参与计算。容量挤出不会产生删除，清除时包含用户当前看到的可同步条目及此前同一设备已知的隐藏旧条目，不能复活旧记录。搜索确认文案明确会清除该设备已知的搜索记录，包括列表之外的旧记录。单条删除只针对选中的键并写删除屏障，清空是只覆盖已见版本的另一种动作。其他来源限定的本机词条沿当前交互处理。搜索词是自由文本，开启前明确提示原文会到服务端，预览列出已有词；明显含访问链接或凭据格式的条目排除。
- 阅读偏好首版全局固定为 `{pageMode, readingDirection}` 组合、`pageTurnAnimation`、`showPageNumber`、`imageFitMode`。模式与方向经现有 owner 的正规化规则作为一个值。按书仅覆盖 `{pageMode, readingDirection}`。同步 set 即使和目标的全局值相同也必须保留，只有显式 clear 才删除覆盖并回到本机全局配置；须经现有 owner 新增区分 set/clear 的增量路径，避免普通写法按值相等删覆盖。不从整份 Preferences 或旧全量按书快照提取字段，恢复缺字段不产生重置。
- 书源订阅共享经过验证的发行身份、规范地址及显示名称，不同步按最近使用排的本机顺序。目标端收到的是共享候选，主动接受才经 SourceIndexService 验证和登记。保留本机活动目录、现有代理/镜像、停用及最近使用记录，已到 12 个目录的上限则继续保留候选，不挤掉任何本机订阅。同步添加、改名和撤回共享更新候选本身，不自动发网络请求、安装或改已加入本机的订阅。被接受的本机订阅在远端撤回共享后仍保留。发行者换地址作为同一已审身份的变更，目标先验证并由用户接受；同地址无受信映射不能自动并到已有目录。
- 备份创建走原本机快照。开始正式恢复前暂停同步，等待在途本地应用到安全提交点。远端最终请求等待有界超时，结果未知则封存该连接的意图、提示可能已提交，仍可继续本机恢复；恢复期间全部入口拒绝新同步。副本 ID、单调序号、连接选择、接收游标、待传操作、未决意图和上次状态均是本机同步元数据，不进备份，不随恢复回卷。恢复成功进入「待重新核对」，新旧本机记录及原待传操作隔离为候选，按仍存在的显式值和已知删除重新预览，不自动发旧队列或使用旧文件缺组/缺键/缺记录产生删除。完整回滚后恢复原调度状态，恢复无法完成时保持暂停和本机证据。

## 协议与失败恢复

- 使用独立命名空间 `koma-device-sync-v2`、版本化不可变提交和每数据集分片。规范 UTF-8 键按固定算法分 64 个一级桶，作品相关记录优先同桶，超预算递归细分。每叶及提交正文上限 1 MiB，每轮已选数据预算 64 MiB。分片按世代及 SHA-256 寻址，先写入、读回并核验字节；名称相同的合法写者只能写相同内容。目录和标准 WebDAV 读写可用即可连接，不要求服务版本、强 ETag、条件请求或文件锁。所填末级目录缺失时只创建该目录，再建应用子目录，不替用户创建祖先路径。父目录缺失、文件路径、WebDAV 方法不支持、认证、权限、超时及具体 HTTP 失败分别提示。清理失败不覆盖原失败原因。
- 每次发布将精确清单及当前父提交编码为正文，以正文 SHA-256 生成唯一 `commit-<摘要>.json`。不写共享可变 head。两个设备从同一状态出发会留下两个并发分支，不会互相覆盖；迟到旧 PUT 仍是原分支。父引用表示完整保全：已选组实际加载所有并发引用，按既有事实合并后归成一份；未选和未知组保留每份不同引用，不下载或应用它们。读取从目录列表及本机持久分支见证出发，直接读取提交并补齐祖先，不能把漏列当作删除。尚未见过的漏列分支只能在服务恢复列出后发现，不声称已经取得服务器全局快照。预览后重读已经变化则重做预览；最终 PUT 前才持久标记已发送，并保存精确提交正文与摘要路径。丢响应先读此路径，未送达则核验父提交及原已选组引用后幂等重发同一正文，未选组保持不透明引用；另一并发分支出现不否定本提交成功。所有本机应用仍只使用原来确认的计划。
- 写操作边界为连接版本和空间。一次同步先从远端读取、验证、计算不可变合并计划，落盘含精确正文的待办意图，再发布不可变提交；没有远端变化时重核当前分支验证。写请求结果不明留在可恢复意图中，重启先核对精确提交和操作版本，过程不生成新编辑。网络期间不锁本机 owner。应用本地前在 owner 写入队列上复核版本，新本机操作保留待传；它改变已确认的影响时，相关本机应用暂停并重新预览，显示远端是否已经提交，不宣称远端可撤回。写入暂存的操作必须来自确认过的计划或已启用自动范围。
- 本地应用同一批的数据和接收游标写入单一可重放的恢复日志，含各 owner 已验证的目标差异、目标修订及源操作 ID。在本地阶段按固定顺序取得所有参与 owner 的写入锁和发布栅栏，普通写入等批次结束，界面读取上次已发布快照。日志先持久化，随后 owner 逐个原子提交，完成标记和游标都持久化后才放行读写、向界面发布及清除确认过的待传项。失败和回滚期间仍保持该栅栏，普通用户编辑不会被回滚覆盖。提交途中退出，启动先沿日志按同一版本重做，再开放普通写入和发布。若无法重做，按日志恢复先前快照并保留待办，恢复仍失败时保持同步暂停并报告具体 owner；远端已完成、本机待恢复是显式结果。普通编辑同样须把成功落盘的变更与待传事实绑在一起；重启能恢复，不在普通 reader 热路径发网络请求。远端写入不触发源执行、第三方追踪、下载或二次上传。
- v2 不自动回收提交、祖先或分片。当前分支已吸收某个祖先，也不能证明离线设备以后不会引用祖先的旧分片；不得套用 v1 单清单世代回收。探针仅清理本机随机 ID 的精确路径，旧探针债务保留 v1 命名空间。后续回收需独立设计副本淘汰与在途写入栅栏。
- v1 是一次显式迁移：既有连接先暂停自动提交，正常预览显示迁移说明，确认前固定并重核旧清单摘要；迁移时对旧引用核字节并完整复制到 v2，包含未选组和不透明组的远端保全，但不应用本机。开始使用 v2 后保留 v1 文件，不再跟读 v1。说明明确要求其他设备更新 Koma 并确认迁移，旧版后续修改不会进入新目录。旧连接不静默迁移。既有未决 v1 提交先按原收据恢复，再进入迁移核对。
- 调度共用串行任务。启动、回前台、网络恢复和落盘写入触发批量同步。前台退避到期有未送改动可自重试，退出等下次合法触发，无后台常驻。活跃阅读收到远端较新位置不自动跳页，应用下次正常打开时生效。重复拉取相同快照不重建书架、偏好或设置界面。
- 正式连接只接受 HTTPS，不允许跳过 TLS 证书检查。自动 HTTP 重定向关闭，遇到重定向让用户更新到可验证的规范目录。后续请求限定于经确认的 origin 和根路径，避免同源其他目录收到凭据。账户和口令仅本机安全存储，日志、同步、备份和探针无凭据。首次启用说明 HTTPS 保护传输，服务管理员仍能看到已选数据及清单保留对象。用户撤除某组/断开停止收发，远端记录的删除与恢复点留存独立说明。公开目录必须是已信任发行者的规范地址，无登录参数、路径凭据或不可信跳转；自定义私人地址不共享。测试用局域网临时 HTTPS 服务和受信测试证书，正式策略不因测试放宽。
- Huawei Cloud 和自建服务后续评估。复用数据范围、身份、合并和用户状态；WebDAV 对象、目录和提交分支不泄漏给各数据所有者。华为云若按表同步，必须另外验证平台实际事务、删除语义和本机数据适配。

## 独立评审和验收

### 独立验收用例

先用合成 A/B 数据和可选的第三逻辑副本重跑确定性场景，再由不同代理在 197、103 上走实际用户路径。逻辑副本不需要第三台真机。两层都固定候选提交、数据、服务证书和故障参数，分别记录实际结果。

另外由未参与界面实现的评审者在 197 竖屏和 103 横屏从普通入口检查四类目的页及设置搜索。连续观察进入编辑、核对及两种返回的原生转场，不以四张终态图或节点存在证明动画。覆盖保存失败/取消、零范围保存、暂停保存同空间口令、首次核对取消、范围取消、暂停重开及精确未决恢复。每条差异直接比较两侧值和当前选择，摘要及时更新；确认动作只在有效计划上出现。管理页返回后保留正确状态与滚动位置，原连接错误/成功时间不被草稿覆盖。所有能力可达与数据结果都要核对，技术测试通过不能代替完整流程与可见界面验收。
