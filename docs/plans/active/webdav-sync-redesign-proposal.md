# Koma WebDAV 同步重设计

起点是两台设备之间的日常续读。用户读到新章、新页，换一台从历史或书架点「继续阅读」，应用自己收发并恢复位置。正常同步在原页面安静完成，阅读中的页面保持在用户手上。本文记录重做合同和待确认的界面。工作区的空闲节流属于独立止损，完整重做与设备验收尚未完成，实际证据见 `WEBDAV_AUTO_PROGRESS_STALE`。

原故障有实证。现用 WebDAV 的 6 次提交、7 个分片都没有阅读数据。使用现有线上数据跑接收逻辑，应用了 4 项分类与订阅记录，阅读 0 项，整轮仍记成功。另已本地复现旧的续读差异挡住新页码、确认所有可见项后仍提示核对，以及页码核验失败连带漏发历史。

## 日常使用

- 入口沿用「设置 → 备份 → 同步 → WebDAV」，连接编辑保留独立路由。保存只验证并保存连接，取消或失败继续用原连接；新目录或账号保存成功才停用旧连接，新连接由用户开启。开启服务和勾选数据范围就是收发授权，普通首次连接、加组及接收均不进入核对流程。同一连接升级保留已选范围、暂停与仅手动选择。
- 日常历史、章页、收藏等变化自动合并。原来的「差异待核对」退出日常路径。真正需要用户决定的项目只在对应位置说明具体影响，例如应用移出书架会影响带本机笔记的作品。其余数据继续同步。
- 「同步」总览列出同步服务及共用的「同步内容」。内容选项在本机保存，沿用升级前的勾选，可以在配置服务前更改。换连接或断开服务时保留选择。各服务独立启停、配置、记录结果和调度。WebDAV 页提供「启用同步」「编辑连接」「上次同步」「立即同步」，标题栏原生更多菜单包含「自动同步」和「断开连接」。新连接开启后默认自动，已有仅手动选择继续生效。手动和自动共用收发逻辑，普通请求不锁导航、范围或连接表单。
- 正常自动同步安静完成。手动结果优先显示本次实际上传、接收的阅读记录数，其他组可展开。已选阅读但确无变化时显示「本次没有新的阅读记录」。仍有待发送、读不到已见版本或本机写入失败时报告部分完成及原因。例行重试留在同步页，影响续读时在原历史条目说明原因并给直接入口。

## 哪些数据能走

| 现有范围 | 记录及行为 |
| --- | --- |
| 书架与分类 | 同步有规范作品身份的收藏、已知完整章节目录、手动分类、分类排列和归属，以及换源后的书架变更。未读数和阅读筛选用章节 ID 与已读状态计算。智能分类、作品排序设置、笔记和自选封面保留在本机。 |
| 阅读记录 | 同步历史、每本最近读到的章节、各章页码、已读状态和章节书签。未收藏也同步。 |
| 阅读偏好 | 全局可共享偏好和按书覆盖各自合并。按书偏好用与阅读记录相同的作品身份，设备显示配置留在本机。 |
| 书源订阅 | 地址、名称及显式删除自动合并到订阅存储。同一订阅按规范身份去重，不因网络探测失败挡住落盘，不自动安装包。 |
| 搜索历史 | 同步已保存的搜索词、时间和显式删除，收到后进入普通搜索历史。重搜按本机的正常搜索流程。 |

书架与阅读记录默认选中。其余三组默认关闭。凭据、会话、带凭据的地址、本机文件路径和下载文件不进入业务分片。记录是否能跨设备使用由统一数据格式与声明能力决定；缺包、未登录或当前无法打开仅影响使用，不能拦接收。

- 阅读器实际保存章页时，把本机的书源身份、作品 ID、章节 ID、页码和实际修改时间交给同步。历史与该次页码以同一阅读动作标识关联、同次落盘，快速换章也按每章各自保存。补登记现有本机历史和章页，原时间和删除信息随记录保留。收到的记录写回本机时保留原版本，防止回填变成一次新阅读。
- 所有同步数据组执行通用数据合同，不按书源名称、标识、站点、包版本或哈希设置例外，也不访问站点验证记录资格。作品和章节按实际规范身份定位，旧记录有可用标识时补登记，无法匹配时原记录保留。
- 「最近阅读」排序使用收到的实际阅读时间。排序方式和正倒序由各设备分别保存。
- 换源选「保留原作」时同步新增书架项；移出原作时把它与目标作品绑定，接收端在同一次书架写入中确认目标及所需的手动归属后才移出原作。目标缺失、待合并、接收失败或已被取消收藏时，保留尚未移出的原作。移出时保留本机笔记与自选封面的既有确认。迁移时选择的章节进度仍由「阅读记录」组收发，沿用现有章节匹配，跨源不照搬页码。
- 历史可以独立接收。缺源时显示书名、源名、章名和原保存页码，提供查找入口。续读使用接收设备的书源和登录状态获取当前章节，恢复已保存的原图页序号。页数变化时沿现有确认入口处理，同页数内的图片重排无法凭页序号识别。只有对应动作的章与页位都持久应用时，才计作一条完整阅读记录。仅收到历史时说明「页位待更新」，本章原有旧页位仍作为可用的本机位置。
- 书架和历史各自附带可用的书源封面地址，用独立数据集兼容旧客户端，接收时补空白。保留本机已有封面和自选封面。封面不可用时其余数据继续收发，旧封面引用留待恢复。

## 怎么合并

- 阅读续读使用操作版本判断先后。已经看到远端后产生的新进度可正常同步，包含主动往回读。章页相同时合并阅读时间。各自从旧版本保存且章页不同，本机未确认的进度保留在待发队列，远端位置保持可用。两端都已并发发布时保留两个版本及各自已选位置。续读沿用现有选择对话框，选择后立即保存所选章页并记录一次覆盖两边版本的操作。只打开同一章同一页时产生的历史时间变化不会补登为新进度。首次启用时的旧数据保留原有合并行为。
- 每本最近读到的章节、各章页码、已读、书签分别更新。某本书有无法确认的旧续读值，新章页和其他书仍可收发。
- 删除和重置是显式操作。移除历史只改历史与最近续读。标记未读按一次操作写入该章的未读和回到开头。书签独立。未观察过删除或重置的旧自动保存受原保护。用户随后明确重读时产生新进度。清空只作用于操作时已看到的历史，另一台未见的新增阅读保留。未读落地后，后续同步使用同一状态比较。删除标记留在记录中，过期文件回收不会抹掉删除版本。

## 何时同步与如何发布

- 已连接且启用自动同步时，阅读记录落盘后约 1.5 秒、其他已选数据变化后约 5 秒安排检查；回前台、打开历史或退出阅读器立即安排，恢复联网后约 2.5 秒安排。当前节流修补：前台空闲检查从 1 分钟起，连续没有应用新数据时逐次延长，最长 5 分钟。失败自动重试也从 1 分钟起并逐次延长。重做以保存、回前台、进入书架／历史、续读及恢复联网为主；静止前台只做低频发布发现，无变化不取分片、不查旧目录，后台撤掉定时检查。
- 阅读进度落盘后短延迟批量发送，退出阅读器时立即请求发送。切后台先把待传记录落盘，系统提供短时运行窗口时完成在途发送，到期把剩余工作留在队列。断网、挂起或强杀后，在下次有运行机会时自动补发。接收端回前台、进入历史时主动检查，停在前台也轻量追赶。从原入口立即点续读时复用正在进行的拉取，最多等 2 秒后按现有已保存位置打开。迟到结果用于下次打开。健康网络下的续读目标只对接收设备已发生检查触发的换机路径验收，不作为静止页面的轮询频率。
- 目录解析、快照解析与摘要、章节目录分块、远端分片校验、合并与分片生成由 TaskPool 执行。自动同步省略核对页的阅读标签，提交按原始持久化输入和当前版本做校验。合并计算不读取凭据、不落盘，返回后继续核对操作许可和本机版本。已校验分片按内容地址复用，跨分片重复键仍在合并时检查。相同的远端状态无需重写本地同步记录。
- 自动同步的状态文件在后台写完并校验，再在原文件仍对应本次状态时原子替换。后台准备期间发生本机编辑时用新状态重算。发布请求仍等待发送记录持久化，合并后的书架和阅读文件仍经原有事务日志提交。
- 历史和书架下拉都按手动请求触发一轮已选内容的同步，也支持仅手动模式。书架下拉在同步结束后检查书架章节，动画等待同步，检查开始与前台结果通过 Toast 提示，后台结果沿用通知权限。铃铛红点表示有未查看的新章节结果，进入更新页后清除。
- 所有设备按数据集共享分片。阅读记录按作品散列到 4 个桶，书架及目录用 8 个桶，小数据集各用 1 个桶。单桶超过对象上限才再拆分。每次只上传改变的分片和一份清单，已校验的分片引用继续沿用。关闭某个同步范围时，清单继续保留该数据集。
- 每次上传使用独立的分片路径和不可变清单。两个写入即使先后抵达也不会覆盖对方。两份并发清单由下一轮合并，读回新清单后移除它已接收的旧清单。未被任何当前清单引用的文件，在两次间隔至少两分钟的检查中仍未被引用才回收。无变化时只查询一次清单目录，续读只读取当前作品所属的分片。
- 上传完成以本次分片和清单读回成功为准。接收完成以本机数据已落盘为准。无需服务器提供 ETag 或 LOCK。

## 旧数据接续

按本机启停策略启动迁移。自动开启时沿普通触发迁移，仅手动时在下次「立即同步」迁移。通过已有连接读取旧目录及最新记录，保留本机历史和未送达操作。

导入保留旧事实身份与操作版本，按旧空间、记录键、操作版本去重。服务器已核版本与本机迁移回执分开记录。旧基线、待发送操作和迁移中真实新编辑分别处理，缺记录保持未知，旧墓碑与候选保留。只有远端读回和本机应用完成，才在同一次持久提交记迁移完成、启用新发送。失败保留原数据和全部待发操作，重试沿用本次标识。

升级后的设备沿用原 WebDAV 路径。迁移保留远端所有数据集，本机只应用已选的范围。共享分片全部通过读回校验后，应用自动回收原路径下的旧版协议目录。发现晚到旧提交时，先合并进共享索引再回收。失败时保留旧数据及待清理标记，后续同步继续。仍使用旧版的设备需升级后继续同步。

书架兼读原 `shelf`，新版变更写入 `shelf-records`。两台升级后才能互收新版书架变更。旧版已发布的新增与移除没有迁移关联，不能事后推断成换源；新版也不向旧分片发送只有原作被移出的半次换源。

## 验收

1. 使用双端同签名候选，选未收藏的多页作品，正常读到第二章的非首页，分别从阅读器返回及直接回桌面后换机。B 分别刚回前台、打开历史、打开书架及首次检查早于 A 发布时验证收到；静止前台另记实际发现延迟和请求量。增加换机立即点续读以及 B 已在 Reader 中的路径，核对实际打开页和迟到时的行为。两端交换角色，重启后读回。
2. 模拟服务端当前只有分类和订阅。本机已有不同章页的旧历史时，升级能补传。阻断书源额外请求，仍核服务器收到历史和页码。接收端缺源、章节改页、已存在同章旧页或暂缺新页位时，核对历史、位置提示和恢复。另核需要登录的书源记录能收发，凭据及签名 URL 不进入同步分片。另选未单独适配过的书源复验订阅、按书偏好和搜索都没有名单限制。
3. 真实无 ETag 的 AList／OpenList 上，两台同时写同一条或不同条。覆盖超时后迟到、列表漏项、异常序号、设备时钟偏差、进程退出、本机落盘失败、删历史、标未读和重读，核服务器字节与两端最终状态。A 只接收 B 的阅读后改无关书架，B 的阅读记录仍在。A 关闭阅读后修改书架，新安装的第三台仍能收到 A 先前已发布的阅读记录。
4. 用旧目录、旧本机记录、待传、删除和备份恢复覆盖迁移，验 A 先迁移、B 离线用旧版继续读再升级，核对已有 V3 进度、迟到的旧改动和重复导入。分别验暂停、仅手动和未选阅读组，核实际网络请求和本机恢复结果。
5. 一轮手动只完成书架时，界面准确指出阅读仍待传。无变化的一轮只查询清单目录，有变动只读取本机缺失的分片。确认更新一条普通阅读进度只写对应分片与清单，旧协议目录能够自动回收。验证手机和平板的普通操作及真实续读。
