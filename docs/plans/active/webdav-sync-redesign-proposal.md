# Koma WebDAV 同步重设计

起点是两台设备之间的日常续读。用户读到新章、新页，换一台从历史或书架点「继续阅读」，应用自己收发并恢复位置。正常同步在原页面安静完成，阅读中的页面保持在用户手上。本文记录目标合同；工作区候选和实际验收范围见进度文档的 `WEBDAV_AUTO_PROGRESS_STALE`。

原故障有实证。现用 WebDAV 的 6 次提交、7 个分片都没有阅读数据。使用现有线上数据跑接收逻辑，应用了 4 项分类与订阅记录，阅读 0 项，整轮仍记成功。另已本地复现旧的续读差异挡住新页码、确认所有可见项后仍提示核对，以及页码核验失败连带漏发历史。

## 日常使用

- 入口沿用「设置 → 备份 → 同步 → WebDAV」，连接编辑保留独立路由。保存只验证并保存连接。首次启用、改用新目录或新账号、增加共享范围时，一次说明并确认要共享的内容。已启用连接在同目录、同账号、同范围升级时沿用授权和原有启停选择。
- 日常历史、章页、收藏等变化自动合并。原来的「差异待核对」退出日常路径。真正需要用户决定的项目只在对应位置说明具体影响，例如应用移出书架会影响带本机笔记的作品。其余数据继续同步。
- 保留服务自己的启停、自动与「立即同步」。新连接首次启用时建议默认自动，原已关闭自动的连接保持手动。暂停保留本机和远端已有数据。手动和自动使用同一收发逻辑。
- 正常自动同步安静完成。手动结果优先显示本次实际上传、接收的阅读记录数，其他组可展开。已选阅读但确无变化时显示「本次没有新的阅读记录」。仍有待发送、读不到已见版本或本机写入失败时报告部分完成及原因。例行重试留在同步页，影响续读时在原历史条目说明原因并给直接入口。

## 哪些数据能走

| 现有范围 | 记录及行为 |
| --- | --- |
| 书架与分类 | 同步收藏、手动分类和归属。保留全书架入口、分类现有语义、本机笔记和封面。私库和本地作品的归属留在本机。 |
| 阅读记录 | 同步历史、每本最近读到的章节、各章页码、已读状态和章节书签。未收藏也同步。 |
| 阅读偏好 | 全局可共享偏好和按书覆盖各自合并。设备显示配置留在本机。 |
| 书源订阅 | 同步已允许共享的公开目录。收到后沿原入口决定是否加入本机。 |
| 搜索历史 | 沿已有公开搜索的范围和删除规则。 |

书架与阅读记录默认选中。其余三组默认关闭。凭据、会话、私库和本机文件路径留在本机。范围限制应能在对应记录上解释。

- 阅读器实际保存章页时，把本机的书源身份、作品 ID、章节 ID、页码和实际修改时间交给同步。历史与该次页码以同一阅读动作标识关联、同次落盘，快速换章也按每章各自保存。补登记现有本机历史和章页，原时间和删除信息随记录保留。收到的记录写回本机时保留原版本，防止回填变成一次新阅读。
- 公开书源以宿主登记的可移植身份规则接入，校验可信来源、跨账号稳定的作品和章标识、安全字段及实际读取的公开上下文。新阅读由宿主在已有读取中记录公开证据。包可公开分发、作品 ID 的格式和阅读成功仅用于各自原本的判断。旧记录以已核公开身份规则补登记，身份无法确认时列明原因。账号专属内容和私库留在本机。所有导出、迁移和删除标记共用字段范围，仅发送允许的安全定位字段，凭据及签名 URL 留在本机。去掉固定发行版本及包哈希门槛，先在数个常用公开源证实通用规则。
- 历史可以独立接收。缺源时显示书名、源名、章名和原保存页码，提供精确查找入口。定位时优先匹配经宿主核实、同章唯一且与页序号无关的页标识，其次比对正常读取取得的安全有序页表摘要。无法确认顺序时，显示保存位置并提供打开对应章和重试。只有对应动作的章与页位都持久应用时，才计作一条完整阅读记录。仅收到历史时说明「页位待更新」，本章原有旧页位仍作为可用的本机位置。

## 怎么合并

- 各条记录独立合并。已经看到旧版本之后产生的新操作优先。两台离线设备各自改了同一条且无法证明先后时，按稳定设备顺序自动展示一个值，保留另一个候选。下一次真实阅读自然覆盖两者。沿用已有操作版本处理重试和时钟回拨，重读时页码可以往回。
- 每本最近读到的章节、各章页码、已读、书签分别更新。某本书有无法确认的旧续读值，新章页和其他书仍可收发。
- 删除和重置是显式操作。移除历史只改历史与最近续读；标记未读按一次操作写入该章的未读和回到开头；书签独立。未观察过删除或重置的旧自动保存受原保护。用户随后明确重读时产生新进度。清空只作用于操作时已看到的历史，另一台未见的新增阅读保留。

## 何时同步与如何发布

- 阅读进度落盘后短延迟批量发送，退出阅读器时立即请求发送。切后台先把待传记录落盘，系统提供短时运行窗口时完成在途发送，到期把剩余工作留在队列。断网、挂起或强杀后，在下次有运行机会时自动补发。接收端回前台、进入历史时主动检查，停在前台也轻量追赶。从原入口立即点续读时复用正在进行的拉取，最多等 2 秒后按现有已保存位置打开。迟到结果用于下次打开。健康网络的验收从 A 离开阅读器或回桌面开始计时，到 B 原历史可持久读取正确章页，目标 10 秒。
- 继续使用分片。V3 新命名空间按设备划分写入目录。每台设备从本机实际操作累计发布记录和删除标记，接收投影单独保存，迁移数据保留原作者和完整因果状态。先写不可变分片并校验，再发布包含单调序号和摘要的不可变清单。重试复用相同文件与内容，迟到请求无法覆盖更新版本。设备身份按安装保存，常规备份排除写入身份和游标。暂停或关闭某组时，之后发布的清单仍原样保留此前已发布的未选组和未知组引用。
- 接收端列设备、列每台的分段名称，再检查最新段，只读取新的清单及有变化的分片。已见版本漏列时直接核验已知路径。已见序号回退或最高清单缺分片时，沿用最后完整数据并标记待恢复，首次接入可暂用上一个完整版本，其他设备和数据组继续。同一序号出现不同摘要时保留两份并隔离该设备的异常写入。目录缺项只影响发现，删除由显式记录表达。不同设备的目录互不覆盖，无 ETag 和 LOCK 的 AList／OpenList 也可运行。首版保留发布记录与对象，清理单独设计。
- 上传完成以 WebDAV 上对应发布清单可读且分片校验成功为准。接收完成以本机数据已落盘为准。两者分别记账，范围内有未完成记录时显示部分完成或待发送。

## 旧数据接续

旧目录和已发布分片原样保留。按本机启停策略启动迁移。自动开启时沿普通触发迁移，仅手动时在下次「立即同步」迁移，服务暂停时只准备本机数据。以一次本机持久化操作冻结旧发送、记下迁移基线并接管后续新阅读或删除，过渡期间按原时序把新操作入队。先按原路径核实结果不明的旧提交，再导入当前授权范围内的服务器记录、本机历史和未送达操作。

导入保留旧事实身份与操作版本，按旧空间、记录键、操作版本去重。服务器已核版本与本机迁移回执分开记录。旧基线、待发送操作和迁移中真实新编辑分别处理，缺记录保持未知，旧墓碑与候选保留。只有远端读回和本机应用完成，才在同一次持久提交记迁移完成、启用新发送。失败保留原数据和全部待发操作，重试沿用本次标识。

旧版继续使用旧目录，两台更新后才共享新空间的变化。后升级的设备再次检查旧目录，把升级窗口内已经发布的旧记录按原版本补入。此过程在 WebDAV 管理页显示一次状态。同范围、同账号升级沿用授权，新增可共享来源或内容属于范围扩大，一次说明后启用，按组管理。既有 v1 连接按原明确迁移入口确认一次。

## 验收

1. 使用双端同签名候选，选未收藏的多页作品，正常读到第二章的非首页，分别从阅读器返回及直接回桌面后换机。B 分别停在历史页、刚回前台、首次检查早于 A 发布时都能在验收时间内收到。增加换机立即点续读以及 B 已在 Reader 中的路径，核对实际打开页和迟到时的行为。两端交换角色，重启后读回。
2. 模拟服务端当前只有分类和订阅。本机已有不同章页的旧历史时，升级能补传。阻断书源额外请求，仍核服务器收到历史和页码。接收端缺源、章节改页、已存在同章旧页或暂缺新页位时，核对历史、位置提示和恢复。另投放私库、账号专属记录和签名 URL 哨兵，核服务器对象符合授权范围。
3. 真实无 ETag 的 AList／OpenList 上，两台同时写同一条或不同条。覆盖超时后迟到、列表漏项、异常序号、设备时钟偏差、进程退出、本机落盘失败、删历史、标未读和重读，核服务器字节与两端最终状态。A 只接收 B 的阅读后改无关书架，B 的阅读记录仍在。A 关闭阅读后修改书架，新安装的第三台仍能收到 A 先前已发布的阅读记录。
4. 用旧目录、旧本机记录、待传、删除和备份恢复覆盖迁移，验 A 先迁移、B 离线用旧版继续读再升级，核对已有 V3 进度、迟到的旧改动和重复导入。分别验暂停、仅手动和未选阅读组，核实际网络请求和本机恢复结果。
5. 一轮手动只完成书架时，界面准确指出阅读仍待传。用 4 台设备、每台 1024 次历史发布的场景，目标为无变化的一轮至多 9 次目录查询、零数据分片下载，有变动只读新的清单及变动分片。由独立代理复审数据与故障恢复、另验手机和平板普通路径及真实续读。
