# Koma 执行规则

本文件规定如何交付，不维护当前进度。AGENTS.md 只保留跨任务原则和本文件入口；具体产品决定与当前结果归 [CURRENT_STATUS.md](../CURRENT_STATUS.md) 原项，公共实现旁说明技术边界。改变决定时更新原处及失效引用，不把一次纠正追加到所有文档。

## 强制先读：禁止编造记忆与无依据确认

- 每次开始、压缩或交接后，以及回应用户纠正、历史要求或既定决定前，必须先读本节。
- 严禁编造、补齐或冒充记忆。用户当前的纠正可作为当前指令执行，但必须如实说明信息来自当前纠正，不能说成自己记得、早已知道或已经独立核实的历史。
- 只有当前可见原文或实际查证的原始记录支持时，才能声称“你之前要求过”“我记得”“已经确认”。摘要、交接、记忆页、工作单和当前实现只能提供线索，不能冒充原始对话或查证结果；日期、原话、因果和授权范围均不得猜补。
- 不知道就明确说不知道，未查证就明确说未查证。禁止为了附和、安抚或表现得记住了而使用无依据的确定语气；发现先前无依据确认，必须撤回并澄清真实信息来源，不能继续把它写成历史事实。
- 用户禁止查询时立即遵守，不检索、不凭空补造答案。仅回答当前已知内容，不能把“不许查”变成虚构记忆的理由。
- 工作单中的“用户正在使用”“禁止操作”等限制必须区分：用户原话、实时占用证据、助手推断。助手写的记录不能再被当成用户下令的依据；一次占用不自动成为长期禁令。与已有明确授权冲突时先查原始消息，不能凭旧记录停用已授权设备。查明错误后同时更正当前限制、引用和持久记忆，原错误及取代证据保留。

## 指令优先级与工作责任

- 用户最新明确要求优先于旧计划、自动唤醒、摘要和历史文档；已确认的产品行为及禁止项持续有效，除非用户明确改变。新任务不自动推翻既定决定。
- 当前任务以可用的用户结果为目标。主执行者主动负责完成任务所必需的入口、关联页面、公共状态、失败恢复和调用方，不以“用户没有逐项点名”为理由漏做；也不以主动补齐为理由改变已确认产品取舍。
- 设计与实现的错误由执行者承担。沟通直接说明问题、改动和结果；限制只在影响用户判断或行动时说明，不在每个结果后附带免责话，不拿用户曾经批准、测试通过或工具限制推卸错误。具体未验范围持续记在原工作单，避免在对话里反复堆砌。
- 对已有授权范围内的必要工作直接执行。只有确实需要改变既定产品行为、扩大权限或作不可逆操作时才提问；先完成可独立完成的调查和准备，说明精确差异。不得反复请求已有授权，或把方案责任转交用户。
- 用户插入问题或纠正不自动终止原任务；用户要求暂停、只分析或先整顿工作方式时，停止相冲突的操作，自动唤醒不得越过这一要求。
- [CURRENT_STATUS.md](../CURRENT_STATUS.md) 是 App/中文源唯一当前队列；共享 Reader 用已指定的跨宿主工作单。先接续实际 owner，单项缺条件不影响其它安全且已授权事项；不能从少数摘要得出全部无事可做。
- 支撑脚本、文档、测试和构建只服务当前交付。不得用整理状态、增加测试、局部提交或回答问题代替产品修复，也不得为维持忙碌重开已接受路径。
- 只在当前目标完成、用户明确暂停/替换，或完整剩余范围逐项有具体阻碍且无安全替代时结束。未完成时不得仅宣告下一步后停工。

### CURRENT_STATUS.md 是给用户看的 bug 进度页

- 读者是用户，不是接手代理。每项回答四件事：用户何时报的、已经过了多久、现在做到哪一步、还差什么或卡在哪里。完整计数始终以 snapshot 的项数和 kind 现算，禁止手写“N 项未完成”。
- 首页正文只写当前结论：正在做什么、是否卡在设备或权限、下一步。禁止把 CI 编号、release/tag、commit hash、字节数、文件数、哈希、逐个测试通过和日志路径放进正文；这些只进原项证据字段、work order 原文或 archive。
- 每项必须保留提出时间及来源；原始时间查不到就显示“原始时间未核实”，不得用登记时刻冒充用户提出时间，也不得用“工时未知”一段长句填空。已经验收或搁置的项不再占首页篇幅，但保留可切换查看。
- 剩余工作明确依赖外部账号、官方原件或上游服务恢复时，在原事项保留已核证据、未知范围和恢复条件，标记“等待外部条件”，移出未完成计数。仍可在本地继续定位或验证的部分留在未完成队列；原因不明不能写成外部故障。
- 工作记录、交接和过程时间线写进 archive 或原项字段；进度页只保留能回答“我还有多少问题、等了多久、推进到哪”的信息。更新进度时不得重写、压缩或删除既有条目、owner、边界及证据。
- 每次实质推进（完成一次修复、完成一次设备验证、确认一次失败、改变一次结论或恢复一次设备状态）必须同时更新对应事项的 status/result/remaining，并在 snapshot.timeline 追加一条带时间、标题、结果边界的记录，且更新 updatedAt。只改事项字段、不追加 timeline，视为没有向用户报告本次推进。
- 改动进度页前先读本页；页面版式变更须保留现有筛选用法，不得为了排版重做信息结构，也不得未经读回验证就交付。

## 修改前：先建立依据，不能由实现倒推正确性

- 修改既有界面、组件或参数前，必须先查组件及受影响调用方的修改历史：读取当前未提交差异，按文件和符号执行适用的 `git log --follow`、`git log -S/-G`，并用 `git show` 或 `git blame` 定位引入、调整、撤销该行为的记录；再核对原始用户要求、相关调查分析、决策取代关系、验收和已拒绝方案。不能只读当前数值或公共组件默认值就提出修改。
- Git 历史不覆盖全部开发决策。未提交 WIP、归档记录及原始对话中的有效决定同样必须核对；未提交、压缩、交接或归档都不使决定失效。未查清来源就明确未知并保留现状，不能把查不到当成可以重做。
- 界面评估先证明具体用户任务或使用状态存在问题，再决定是否改动及选用组件。不同于默认值、使用自绘组合、与其他页不相同，均不能单独证明缺陷；禁止为统一模板或参数反复重做已定设计。 先描述原图实际可见的异常，再定位它的状态及布局归属；不能先挑一个方便修改的高度、位置或颜色，再用解释把它包装成已定位的缺陷。用户反例出现后撤回不成立的判断，不能追加其它主观“问题”凑结论。
- 既定决定只因用户明确改变要求、新的实际反例或具体依赖变化重新审议；必须说明新证据及原决定的理由为何不再成立。拟改动前留下“修改对象/历史来源/原理由/本次重开依据/允许差异”的可查记录；缺依据不得反向立项、修改或交给代理。
- 请求批准不能代替调查与方案责任。向用户提交候选前必须完成上述追溯，主动说明与既定决定的冲突；不得拿小 diff、组件默认值、笼统“规范”或用户点过批准作为无依据方案的免责理由。

- 移植现成功能先读参考实现的完整行为，包括入口、菜单层级、状态归属、默认值、无配置及失败状态、后台处理和返回关系。先完成忠实、可运行的完整路径，再考虑优化；不能只移植处理库后自行拼装产品。
- 复用现有实现及其责任边界，先核所有者、写入/失效、异步回调及全部真实消费者。公共能力不能在多个页面分别维护持久状态或相互矛盾的可用性判断。
- 只做必要的宿主、路由、持久化及平台接口适配。每处参考差异说明实际不兼容点；“更合理”“小 diff”“更适合本项目”都不是自行改设计的依据。适配触及已定产品行为时，先取得该具体差异的允许。
- 架构检查必须改变实施：确定功能属于哪个已有模块、配置作用域和生命周期、哪些现有调用方需要同步修改。不得把孤立新增组件、代码存在或接口连通当成完整接入。

## 实现时：保留产品，完整处理关联影响

**未经用户明确允许，禁止更改样式；修 bug 也不例外。**

- 已确认的正常功能、外观、数据及操作是改动边界。授权修复包含必要关联实现，并非只改用户逐字指出的局部；但圆角问题不授权改尺寸，按钮问题不授权删入口，局部问题不授权重做公共 shell。
- 用户已明确采用的更正按该允许直接实施，不再以“样式需批准”为由保留已被明确要求纠正的错误。未允许的差异仍须先说明和取得决定。
- 全局长期配置、当前会话操作和公共处理能力分别归已有 owner；菜单、设置搜索、路由与能力可用性同步接通。不得摆放无法使用的入口，或让无配置、未选择、加载及失败状态消失在正常状态之外。
- 缓存服务可用首帧：有可用快照时先保留内容和行/图标身份，后台检查后差量发布；不把空白→读缓存→整表重建当作缓存完成。重型 I/O、解析及图像处理不得同步挤入入场动画；检查所有真实消费者，不能只在当前页补一份缓存。
- 预载、原图准备、图像预处理和最终显示是不同阶段。功能需要预处理时必须接入现有准备链，检查预载页也实际消费该能力；当前页处理成功不能证明预处理已覆盖。
- 失败与部分成功必须如实反映已知/未知，保留仍可用结果。恢复只处理对应失败，不重放无关操作、不改设备/服务环境制造通过。
- 原因未知写未知；不靠任意延时、持久状态注入、清数据、改权限/网络或参数试错消除现象。
- 发现方向错误立即停止并撤回不符合边界的差异，保留失败；不得笼统回滚整批 WIP 或删除已确认成果。临时诊断和临时设备状态恢复后读回。

## 验证与收口：先证明用户任务，再考虑测试数量

- 验收依据来自用户要求、原正常行为和已采用参考，必须先于新实现确定。不得改完实现再改测试期望放行；期望确错须有用户决定或真实反例，并留下取代原因。
- 先检查完整普通路径的实际入口、无配置/准备状态、使用过程和返回结果。直接及间接受影响路径都要考虑；公共代码没改、小 diff 或单一消费者通过不证明无影响。
- 少写测试。只保留能执行关键逻辑、失败恢复和必要边界的覆盖；已有覆盖不重复。禁止仅匹配源码字符串、字段写法、组件嵌套或截图数量的检查，也不新增 UI 正则、hook、命令拦截或自造门禁来代替判断。
- 测试证明其实际执行的逻辑；编译/CI证明构建；安装证明包已安装。它们不能判断产品层级是否合理，也不能替代真实使用、图像可见、预载处理、转场连续性或外部服务结果。
- 界面和交互用当前签名包走普通入口，顺序观察完整动作和返回，先找画面异常再对齐日志。转场/滚动看连续原片；不得挑稳定帧、只看缓存终点或以布局节点存在冒渲染成功。
- 核对前台 App、实际包、设备型号、方向/折叠及窗口；只比较同状态、同 viewport。任一可见反例使相关结论失效，脚本/日志/代理 PASS 不得抵消。
- 只通过具名版本、设备和路径。未验证写未验证；真实进程死亡与同进程回滚分开，未配置外部服务的功能不能冒真实调用通过。已有效验证的修复不默认要求原故障设备或指定设备重复验收；设备和路径记录保留验证范围，不自行增加关闭门槛。已接受路径按其范围冻结，只由新反馈、真实反例或具体依赖变化重开。
- 提交前审精确 diff、权限范围及关联消费者；按有效授权分组提交和同步。构建、安装、验收、提交、推送、发布分别记事实，不自设重复批准门，也不把未授权发布扩大成不提交有效工作。
- 未经用户明确允许，不改版本名或 versionCode；重新发布同一版本时沿用现有版本字段。

## 文档与沟通：修改事实时维护原处

- 同一产品决定只在既有权威位置维护，其他文档用链接；实现旁保留为什么及何时可改，进度留原工作单。历史用于查证，不自动派工。变更行为时必须同时纠正冲突/失效引用，不能把维护责任留给用户定期全局排查。
- 默认阅读链中的技术/开发文档只描述当前有效合同、职责和状态；历史修改与决策取代经过另存，当前文档不链接历史档，明确查证历史时再按需读取。AGENTS.md 不存具体功能需求、临时状态、设备地址、实现参数、证据编号或待办清单。模块规则按当前工作选读；不得把本轮方案、验收状态和长期原则揉成一条永久禁令。
- 批评、错误表现、候选、采用决定和验证结果明确分开；登记前核原话方向，不能把用户投诉的错误写成应保留的边界。规则变更本身也按原意审 diff。
- 沟通给出新发现、实际变化、证据边界及仍未知处。回答“为什么”须解释实际判断错误，回答“怎么改”须给具体执行方式；不得把用户的话扩写成自己的发现，也不以认错、保证或测试数量替代行动。 检讨必须交代可追溯的错误判断、它如何进入代码或记录、阻止重犯的公共约束及实际落实结果；不用“当时只顾……没有……”描述作解释，不反复套用“复述问题＋失职标签＋道歉”代替原因和纠正。
- 当前结果、剩余动作及 owner 只更新原工作单；交接保留原目标、限制、失败、WIP、设备恢复和下一未完成动作。下一轮须接续这些事实，不能凭压缩/换轮次撤销要求。文字记录不等于执行保证。
- 更新日志按“新增／修复／优化／已知问题”分类，不把未解决或未验证写成已修复。

## 权限、工作区、设备和数据

- 未经用户明确允许不得创建任何 worktree；保护 WIP、并行、隔离验证或打包都不是许可，不能用额外 clone、源码副本或子代理规避。仅在获准用途内使用已允许的 worktree，完成后合回原主仓并退出。
- 不默认建子代理；只按用户明确允许范围分工，复用现有 owner，不重复派同一项。主执行者审真实 diff 和证据，设备串行操作。保护用户 WIP、数据和素材，不广泛 add/reset/clean。
- HarmonyOS 源码、构建、设备操作先按 `harmony-mandatory-preflight` 读相应开发/设备技能；同任务流程可复用，不能因压缩全量重复预检制造等待。不确定 API 查官方合同、版本及权限。
- 设备、截图、日志、UI 操作还必须读 `harmony-run-device-diagnostics`，开始前说明选用技能和原因。用户选定设备后用完整 target 解析并经租约执行；状态和取证统一走项目 checked manifest，直接租约 HDC 仅限发现/重连、`shell echo`、启动读回和文件接收。
- 锁屏是流程内状态，不是阻塞理由：唤醒、在非通知区域滑开、解锁后写超时并读回要放在同一清单连续完成，再进入 UI。不得因为锁屏停工、换设备或改去启停模拟器；模拟器不得替代用户指定的真机，其结果不写入验收。
- HDC 及任何可能调用 HDC 的 helper（包括只读/dry-run）必须在沙盒外执行。实时解析当前授权 target 并持有效租约；不能用旧地址、端口、租约或沙盒连接错误判断设备离线。
- 设备号只是故障线索，不扩大授权。允许日志不等于允许点击、启动/安装、切章、清缓存、改设置或写数据；已有明确测试机及范围授权持续有效，范围不明先查本地。禁止操作的设备、用户搁置项不得复活。
- 状态操作复用项目 checked manifest 和语义路径；正常控制前建立唤醒/超时等技能要求。动作注入不证明跳转。返回失败先保留当前证据并核前台/路由，不连续 Back 猜页面，禁止越出授权 App 后继续通用点击。
- 不自行启停/重启模拟器，不清用户数据/缓存。失败也必须独立执行设备恢复和释租，不能因截图、快照或页面断言失败跳过清理；读回最终状态。
- 签名沿当前已验证的本地构建配置和该 bundle 的既有 profile，不生成/替换证书凑安装。环境文件、配置路径可能变化，先核实际存在性；旧文档固定路径不冒当前事实。签名秘密不进源码或日志，macOS 不用 Linux dev.sh。替换包前核包身份与既有签名，不能清数据绕过冲突。
- 首版产品范围与对外边界以已采用产品决定为准；不内置源或源市场，不宣传全网/免费/聚合。普通界面不出现内部 QA/debug/path；不复制 Aidoku/Homo 代码或资源。

### 书源、验证和缓存

- 统一搜索的来源范围与结果显示是两个独立维度：原漏斗保留来源筛选，右侧文字菜单显示并切换“显示全部／仅有结果”。结果显示只投影已经返回的数据，不重新搜索；未配置的私库不显示空分组。标题、作者、章节名匹配及原排序保留，匹配和排序在后台任务执行，结果按可见行创建；不能为提速删搜索字段，也不在行绘制时重扫全部源或同步检查全部图标。
- 书架字段查询由 `LibrarySearchQuery` 在规范化文字之前解析，过滤仍由现有后台匹配任务执行；库内条件不发送给在线书源，迁移的在线搜索保持独立。详情书源入口使用书库持久来源身份，空关键词列出该源的入库作品，不依赖书源仍已安装。查询自身的来源条件及历史范围不覆盖用户保存的全局来源偏好；历史重进须恢复同一范围。没有标题关键词时不生成标题匹配等级，未知未读数不冒充零。

- 已安装源的系统分享只导出源包，不能夹带源设置、注册表、验证会话或书库数据。有原归档时保留原字节；备份恢复未保留原归档时，只从源清单、WASM和已有图标重建合法包，不能把恢复记录冒充归档。异步准备独立缓存副本后交系统面板，保留接收方读取所需的文件生命周期；不能因源更新、删除或再次分享覆盖在途文件，也不把拉起面板当作已发送给他人。

- 漫画160普通网页的鸿蒙识别兼容只属于当前 Web 实例：初始地址须为已核的 www/m 两个 HTTPS origin、无验证会话，且默认 UA 同时含 OpenHarmony/Mobile、没有 Android/iOS 标识，才在保留全部字段后追加 Android 标记。依据与原详情实测保留在 CURRENT_STATUS 的 SOURCE_WEB_SESSION；不扩大到全局 UA、源 HTTP、验证 sheet、缩放或导航拦截。站点两端都已正确识别 OpenHarmony 的新证据出现后才重新审议此兼容，不能因通用封装重构丢掉或全局套用。

- 统一搜索遇到源明确返回的验证/登录要求时，按源独立认领，并串行复用现有验证半模态；其它源继续返回结果。依据为 CURRENT_STATUS 的 SOURCE_WEB_SESSION 中当前已采用要求。通过后只重试该源原请求一次；关闭、再次挑战、切换查询/筛选或离开页面不得循环弹出或重放旧请求。源包身份、设置版本及当前页面共同决定回调是否有效；保留单源验证的 Cookie/权限/UA 和样式边界；漫画屋仅按原事项明确采用的源及 origin 特例使用 Web 引擎默认 UA，其他源仍沿原失败请求身份，不扩大 Cookie 或权限。原生验证得到的单次响应只由精确匹配的原请求消费，无关并发请求不能清走；取消对应会话时仍清理它。站点验证后跳到同源其它地址404、但已有明确 clearance 时，可在原认领仍有效时探测原GET一次；404与Cookie都不能直接授予成功，只有原GET真实2xx且无挑战才能回流，失败保留手动操作。原地址的主请求错误、其它错误和跨源地址仍保持原拦截边界。不得因全量搜索汇总迟到覆盖已验证源的新结果。网页缓存命中或304重验证后展示的200不代表本次线上200，也不能证明验证已通过。

- UI内存状态键须遵守AppStorageV2平台字符约束，并与持久偏好键分开核对。语言状态的具体边界见 `state/LanguageState.ets` 旁注及 `i18n/LanguageSettings.ets`：消除连接开销不能删除locale响应式依赖、改语言偏好或破坏启动恢复。

- 已收藏源漫画的详情归现有 Comic/Library 持久域；进程内详情缓存只补充热快照，不另存一份章节表、正文临时地址或源凭据。已有详情先呈现，后台重验不能重置加载态或自动弹出验证；显式刷新保留原反馈与验证恢复。更新以实时书库对象为基准，保留分类、章节页表和阅读进度；相同结果不重复写盘或发布书架变化。扩展持久字段时同步所有复制、分类变更和书库更新路径，不能在下一次更新时丢掉它们。 作品的公开书源名称随详情快照保存；卸载前由原书库事务保留最后已知名称，缺源详情沿既有回退展示。缺源不删除书库、下载和进度；旧备份未带名称时不猜补身份。

- 已安装源的展示排序须保留原本地化名称、比较器、同名ID顺序和DTO身份；单次排序内可先逐源解析名称，不能在每次比较中重复校验元数据，也不能把名称缓存跨locale或源变更保留。Browse模型刷新时，仅完整展示DTO值相等才复用本模型的原行对象，仍发布新有序数组；字段改变、移除和失败恢复沿原合同，请求及源包有效性继续读实时Registry，不由展示对象决定。减少重复解析或行输入重建不能代替普通路径的性能验证。

- Browse 的源展示投影同时受所选页签与根导航实际可见性约束；被源管理等页面覆盖时保留当前行，返回可见后消费最新 Registry revision 一次，未变更不重建。远程服务可用性的页签激活刷新仍由原 owner 独立处理，不因延后源展示而漏掉或增加该请求。

- 源可用性核验按用户要求覆盖全部85源，须对照固定版本Mihon/Keiyoushi真实实现的设置项、默认值、实际消费及能力/导出；静态cap、schema通过或参考文件取回不等功能完整。网页入口仅在已有合法主页地址时显示，源生产包校验主页必填；未知/空设置schema不显示入口，单源schema失败不得污染全局已保存设置状态；确有存储读取失败时保留有效入口并显示具体读取阶段，不得以“设置验证失败”等泛化提示代替处理。源设置迁移须核真实消费，敏感cookies/userId/token不得因有导出就开放普通明文持久。当前实现/验收状态以CURRENT_STATUS原源条目为准，不以本规则冒WIP已交付。

- 浏览与书源管理共用语言及内容评级的持久展示筛选；筛选不改变源启用、全局搜索或书库范围，未标注评级不能冒全年龄。浏览按实际声明的语言分组，保留组内本地化名称顺序和行身份。订阅目录合并所有已保存地址，同ID按既有版本及图标比较规则选取，所选条目携带Host赋予的订阅归属；单包、批量安装及更新均消费该归属，不能用最近编辑的地址替代。订阅增删共用公共缓存；移除只撤该订阅候选，不删除已安装源或书库。管理页下拉检查复用原检查owner；浏览仅保留展示筛选与书源管理文字入口，安装和订阅由管理页原生溢出菜单承接，不跨层重复。订阅使用独立列表页，标题栏添加及行内编辑共用公共系统输入对话框；可选名称及发布者项目页合同见[运行职责](../WASM_SOURCE_RUNTIME_DIRECTION.md#订阅身份)，复用既有缓存和安装调度器。语言全选的模型同步回调不能被当成用户清空操作。

- 多地址源更新检查只部分成功时，保留已确认的更新，未查全的源不得新判为最新或未找到；失败原因归现有地址行，单地址重载成功只清该地址原因，不冒全量检查完成。当前已采用的具体文字和范围以CURRENT_STATUS的SOURCE_INDEX_CACHE_REVALIDATE为唯一依据；全部成功和全部失败的原合同保持。普通源包行按当前采用范围展示身份信息和可用操作，不逐行重复全局检查状态；渲染避免每行重复扫描全部源并记录交叉依赖；帧缓存只用于渲染，更新完成直接消费本次返回的DTO，异步设置回写校验当前packages的对象身份及原revision，不能因性能修复读到上一帧结果或丢弃本次有效设置。批量更新的每源完成也复用单包投影；管理页关闭后仍按本次真实安装结果合并公共缓存并重算角标，不能等待页面重入或用旧页面快照覆盖其他完成项。保留最终完整核对及原禁用状态、失败/跳过计数和顺序。在线安装允许两个不同源并行准备和安装，同源重复点击共用结果；登记的同步提交段及失败回退隔离不能丢。普通本地归档在同一调度器中作为排他屏障，等待此前任务结束后单独执行，再放行后续任务；归档身份尚未知时用不含文件URI的私有任务身份，不全局禁用无关源按钮，删除和重复选择器的独占保护保持。当前范围见CURRENT_STATUS的SOURCE_INSTALL_PIPELINE_SERIAL。 管理页可用快照由页面外进程级owner保留；先从已保存仓库索引和当前已安装版本恢复更新投影，供浏览角标及管理页共用；启动和manager入口共用一次异步revalidate，检查中或失败时保留缓存及已知更新，显式检查仍可执行。页面首帧不读盘解析或自动清空；相同DTO/图标身份不重发，完整结果就绪后差量发布。备份恢复或源身份失效后，旧draft不得继续请求后续地址或发布。

- 已存源章节页表绑定生成它的源设置摘要，并随章节持久化及目录合并保留。设置相同时复用；设置变化后只在实际需要该章时重新取页，成功后替换页表及摘要，失败保留原页表且不得标成新设置。空设置兼容旧页表；不清图片缓存、不改离线下载清单或阅读进度，不把此修复改成每次入场全量刷新。摘要取自实际get_pages请求快照，当前设置变化后迟到结果不能提交。

- 用户界面将可安装、更新和分享的阅读源统一称为“书源”（英语 Source/Sources）；协议、资源键、文件格式及内部 package 身份保持。自定义标题栏更多入口沿公共 `komaTitleMoreIcon` 使用系统四点图标，行内操作图标及原菜单行为不因该纠正改变。

### 书库自动化、下载与备份

- 新增 ArkData 持久键时，在 `scripts/backup_settings_policy.json` 对应的存储所有者下明确归类。通用可迁移设置从 `ApplicationSettingsBackup` 的生产白名单读取，独立备份字段、仅本机数据和凭据分别归类。既有遗漏列在 `pending`，不可作为新增设置的默认分类。对新增可迁移字段，在 CI 的备份导出、恢复和读回测试中覆盖非默认值；凭据和设备授权不能混入导出。文件或数据库中的新增设置也要显式接入对应备份域及行为测试。

- 书架更新铃铛进入新章节列表，原检查统计保留为次级入口。原列表样式移入更多菜单后仍保留独立选择子菜单，不把网格/列表平铺为功能操作；二级菜单构建归公共菜单组件实例，原扁平消费者保留原路径。新章记录共用更新/自动下载已有的更新前章节ID快照，在书库变更成功持久化后才记录同一结果域；后台合并和手动检查消费同一规则。目录顺序、数量差、上传时间和旧结果均不能冒新增章节依据。后续检查无新章或失败不清既有新章记录；初始历史不猜补，打开列表不触发全库检查，显式下拉沿原手动检查范围。下拉及菜单检查共用同一刷新指示器，背景检查不再额外叠加转圈；通知只展示本地化结果摘要，内部错误码保留在诊断记录。

- 跨源迁移的来源偏好独立持久化，已选与可用来源分组；可用来源整行加入，已选来源仅通过独立移除键退回可用组，整行不绑定移除；已选来源使用系统拖动排序，结果分组与自动匹配共用该顺序，不另设数字优先级或上下移动菜单。单本搜索与确认归同一迁移页面，不为流程阶段叠加通用搜索路由；结果卡片点按打开迁移选项Dialog，Dialog提供复制、迁移及查看作品，长按直接预览，不在每张卡片下附加选择按钮。确认Dialog只保留目标作品标题；准备、提交及失败反馈共用固定摘要行；失败时原加载位置显示可点击重试，验证入口也留在同行，不在末尾增删错误或操作行造成窗口高度跳变。可用来源沿现有分组列表显示行间分隔。Dialog查看作品先关闭确认，返回保留原搜索结果；批量人工选择返回原批量核对。搜索沿共用多源执行及验证链，明确选择目标后才准备迁移。准备阶段复用现有同源包身份、设置版本及地址匹配的完整详情和目录快照；源变更或目录未完整时仍走原请求，提交前继续校验身份。预览不能自动收藏目标、移出原书或迁移阅读进度与追踪绑定，最终复制／迁移仍走原提交事务。
- 自动检查的分类与跳过规则归 LibraryAutomationPolicy；手动检查仍覆盖全库。新章下载须在书库提交成功后按真实章节 ID 差集入队，共用现有下载槽、暂停及恢复，不用数量或展示顺序推断新章。
- 预计更新日使用章节上传日或首次获取日的日历规律，检查成功后才更新；缺失预计时间仍检查，未到期限制只用于自动检查。该书的预计时间随书库保存，跨源迁移不沿用旧源的预计时间。
- WorkScheduler Extension 不读写 UI 的 XML 首选项或内存书库；UI 提供偏好模板，Extension 读实际数据、生成备份或结果，再由书库 owner 合并。恢复备份使旧任务失效，迟到结果不得写回；没有内容变化不重写全库。
- 后台下载归一个 DATA_TRANSFER 所有者；实际传输和队列仍归原服务。完成时先结束在途进度更新，再撤销持续任务。读后清理等待 Reader 关闭且进度提交，只处理已读下载，保留分类排除与绝对章序，随后刷新已有详情状态。
- 自动备份目录使用系统选择器的持久授权，目录权限不随便携设置跨设备迁移；仅管理自有备份文件和本次取得的授权，不撤掉本地书库依赖的读取权限。源包编码及大书库组装归后台执行进程，不挤入 UI 生命周期。
- 设置首页的「备份与恢复」承载创建动作、备份记录和持久偏好。「创建备份」用居中 Dialog 选择应用内或系统文件、按需启用加密。保存位置是单选菜单，直接保存到文件不生成应用内记录。记录的单一导出动作使用所选快照，取消系统选择器时恢复原操作草稿。手动与自动共用持久内容，只有运行自动任务时才应用计划目录、保留规则并更新运行时间。同一进程重进先使用已成功读取的记录和真实持久偏好，已知空目录也保留。后台对照文件状态，只重读新增或修改的记录，失败保留旧列表；恢复设置成功后刷新偏好。恢复明细点开后计算并用 Dialog 预览，摘要沿用 Dialog 底板，长明细只滚动正文，底部按钮固定，执行前明确提示替换范围。展开与收起在 HDS 点击回调结束后才重排，备份表单复用普通原生按钮的公共操作行，允许校验或解密后留在 Dialog，Dialog 退场后才清理草稿。偏好就绪前不显示虚构开关，读回等值不触发写入。设置搜索只定位该页实际入口。具体改动与验证范围见 CURRENT_STATUS 的 BACKUP_WORKFLOW_REDESIGN。

- 跨设备同步的入口、可发送字段、冲突和恢复边界以[已确认设计](../plans/active/device-sync-design.md)为依据。同步分片只接收显式允许的模型，普通备份规范化时排除本机同步状态。条件提交重试沿用已落盘的操作版本，恢复后的旧意图经用户核对，独立验收以指定候选的设备证据为准。
- 复杂编辑表单沿公共 KomaModalScaffold 的原生模态标题栏、关闭及统一内容材质；保存用公共可选确认操作，固定在标题栏。短选项和层级选择沿原位系统菜单，不为排序/阅读状态或包含/排除/不限另开半模态，不通过互斥行内展开挤动其它操作；菜单选中及关闭状态归现有公共下拉控件。既有查看型半模态未传确认参数时仍只有关闭。
- 章节书签归 ReaderSessionStore 的章节状态，独立于已读和阅读位置；已读修改、继续阅读和迁移不得清掉书签或把书签章标成已读。笔记与自选封面归 Comic，源刷新、分类与对象重建保留；自选图片走本地封面解码，恢复源封面只撤销该覆盖。备份包含自选图片本身，恢复先重建新本机文件，再沿原数据事务提交；失败只回收本次文件，旧资产和旧数据保持可恢复。 个人笔记仅在原字体与实际宽度排版超过三行时显示展开；简介继续保留独立的原展开行为，不能靠字符数猜测换行。
- 阅读统计沿原 ReaderSessionStore 保存真实阅读会话，前台可见 Reader 及其实际页位置决定计时和页数；切章、离开及退后台提交，后台和预载不计入。旧进度时间戳不推算历史时长；备份恢复保留会话，跨源复制不复制统计事实。统计日期按本地日历，章节汇总按当前唯一章节 ID，不由列表展示顺序或重复条目改变计数。
- 追踪服务的连接方式由 provider 配置持有；页面、账户刷新、作品匹配、进度同步和失败重试共用可执行能力边界，不能仅显示入口而在消费者中仍拒绝该服务。密码仅用于登录，验证后的令牌交由原安全存储，普通首选项及备份仅保存公开账户与映射；远端写入保留用户已有收藏状态和其他字段，候选匹配须由用户确认，远端已有记录先读取并保留，远端登记成功后才提交本地绑定；解绑移除本机对应关系与待同步任务。主动断开提交后保持未连接，凭据清理失败可重试，不覆盖为连接错误。 OAuth 已配置时由原追踪服务先生成并持久化待授权状态，再交给系统浏览器；授权进行中界面显示未连接，待授权会话只用于验证回调；AniList 浏览器卡住时重开会发起新会话，其它服务沿用待授权会话。应用注册参数和回调接收由 Koma 管理，用户界面不提供填写或粘贴入口。刷新和断开仅用于已连接或此前成功连接的网页授权账号。 系统入口按回调路径前缀匹配，使系统能分发带片段的 AniList 回调。应用内仍精确核对已注册的 Koma 地址和当前待授权会话，无关链接不得改写账号。Bangumi 新连接走 OAuth，访问令牌和续期令牌同存一条安全记录；旧连接继续读取原个人令牌。Bangumi 匿名授权跳转会丢回调参数，兼容值仅携带固定 Koma 回调；两种回调状态须精确匹配原随机值或其固定扩展值。
- 追踪半模态复用当前详情页按账号和作品隔离的已有结果。每次打开先显示缓存并立即后台刷新，失败保留已有值；同一绑定合并在途刷新，旧结果不得覆盖新编辑。编辑即时显示，保存失败回退并提示。
- 阅读事件自动同步到本书的每个已确认追踪服务，按服务独立重试；手动上传只写当前选择的服务。上传和首次添加追踪取续读记录与已读章节中的最大可识别已读话数，目录位置不能充当话数，远端已有记录的首次绑定继续保留远端值。
- 智能分类是原书库中的命名规则投影，与手动分类分开保存；不能向 Comic.categoryIds 写入动态成员，也不进入手动赋类或自动任务的分类选择器。同类来源、内容分级和手动分类的包含值取 OR，不同类型取 AND，排除项独立生效。内容分级只取作品实际元数据，缺失保留未知；追踪条件消费原 TrackerPreferencesStore 的已提交公开映射，失败回退不发布新成员，备份替换后失效并重读。
- 本地归档文件导入沿原系统选择器、私有持久副本和书库提交链；ZIP/CBZ保既有解码路径，RAR/CBR、7z/CB7、TAR/CBT及图片型EPUB由后台原生解码。EPUB按container、OPF spine及页面内图片引用顺序取图，保留重复引用，不做自然排序或补入未引用图片，不渲染文字正文。目录扫描仍保既有章节描述合同，不能因扩展文件导入的格式检测就新增空目录章节。格式扩展不改变源、下载、阅读方向或原处理链。

### 关于与应用更新

- 关于页沿已采用的 NextE 信息层级和原生更新日志浏览器；应用身份、仓库地址及版本来自 Koma，不复制参考项目的账户入口、群链接或源码许可声明。交流群采用用户指定的 Koma 群名、群号和链接，复用原列表行及系统链接跳转；仅用户更新群信息时更换。第三方许可仍随包分发，不因移除旧主列表入口而删除。
- 应用发布历史由 AppReleaseService 单独持有内存与持久缓存。进入先消费已有缓存，再后台条件刷新；并发检查共用请求，刷新失败保留已有日志，缓存不作为用户配置进入备份。
- 历史日志保留原 Markdown 内容、版本页签与横向切换；打开发布页使用当前选择的版本。普通更新检查只读取公开发布记录，不能下载后自动安装、上传 AGC、创建 tag 或发布版本。

### Reader 迁移与翻译

- 图片处理插件的订阅、目录、已安装算法及选择归 `ImageRuleStore`；订阅信息和已安装内容分开保存，处理链只消费安装集合的不可变快照。订阅页只管理地址与信息，安装、启停、配置、手动更新与卸载归插件管理。移除或修改地址保留安装内容及原来源，不设订阅级执行开关或后台算法升级。App 提供通用运行时与像素接口，不内置具体插件或默认订阅，不按算法名称硬编码分派。书源与插件由清单内容识别且独立消费；目录刷新不等于安装新算法。原图、普通CBZ及目录检查不重置当前阅读的边界保持，协议、迁移与执行预算唯一依据为[插件 ABI](../image-processing-plugin-abi.md)和[订阅协议](../subscription-image-rules.md)。

- 书源正文的气泡文字属于页面内容，须经独立 Host 能力协商。气泡描述随原页身份、书库页表和新下载清单保存；在后台用原图与描述生成派生图，阅读、预载、普通保存分享和 CBZ 共用结果。下载原件及其校验保持不变；合成失败沿原加载失败处理，不能显示缺对白原图。旧下载没有描述时不猜补，缺源本地阅读不依赖在线源设置。


- LLM 提供方按源身份管理 API 配置或 Codex 登录，消费者绑定源与模型，不在源删除后隐式改用其他账户。消费者表单只保存绑定与翻译选项，不覆盖源登记表；管理页的增删通过原 revision 同步到保留的页面。OAuth 凭据沿 Koma 原子安全写入 owner 保存；自动轮换必须核旧凭据且不推进用户配置 revision，手动登录/退出才使旧处理配置失效。界面只保连接状态与公开账户信息；用量缓存按源和账户隔离，不保存凭据、不进入备份，旧页面或已删除源的迟到结果不能回写。模型列表取所选提供方的实际目录，不自造共用模型白名单。

- 阅读控制栏的单双页按钮只控制单/双页，方向按钮提供从左到右、从右到左、纵向分页和连续滚动四个互斥方式；阅读设置与全局阅读设置复用 `ReaderDirectionMenuItems`，设置命令经 `readerControlDirectionSelection` 成对更新模式和方向。连续滚动时单双页操作沿控制栏的禁用状态；水平顺序在纵向方式下仍保留为休眠值。不得另写一份混入连续滚动的单双页菜单，或把连续滚动降成“从上到下”的别名。当前依据为 CURRENT_STATUS 原 READER_SETTINGS_PLACEMENT 项。

- NextE 阅读能力迁移沿用户已采用的现有阅读设置和更多入口，具体允许差异以 CURRENT_STATUS 的 NEXTE_READER_FEATURE_MIGRATION 为唯一依据。裁边强度与超分配置复用 ReaderPreferencesStore 的有序写入、备份与 runtime 发布；处理器消费已发布配置，不能另立持久 owner。原去白边默认 false、超分默认关闭；选择或下载模型不自动开启，模型资产须校验后才可交原生处理。原图下载、预载、导出和进度仍由原宿主负责，处理失败保留原图；检测/增强结果只能经现有 Kit 的 crop/variant 合同进入画面，不改 Kit、目录顺序、阅读模式或既定转场来适配功能。

- Reader 即时控制与全局长期配置分责；具体采用入口、分组和日志归属见 CURRENT_STATUS 的 NEXTE_READER_FEATURE_MIGRATION。增强模型未选/不可用仍保留可见开关；模型选择与模型文件管理沿 NextE 原职责，不能自行合并成下载选择菜单。各入口消费同一配置及能力状态。
- 阅读中的设置使用公共半模态的三类动画分段（阅读模式／常规／滤镜），各页保留滚动位置。滤镜直接编辑现有显示配置，预览期间遮罩透明但下层仍不接收输入；共享工具栏只作临时隐藏，不修改原可见状态、窗口尺寸或会话。离开滤镜或关闭设置恢复正常展示。分段栏保留内容自适应尺寸，公共半模态使用 HDS 原生标题的空间渐变模糊作背板；列表起始按分段栏实际高度留出间距并可滚入下方。HDS 根据当前列表滚动偏移启用渐变，零偏移使用半模态本身的背景，首行保持清晰；不增加玻璃背板、分界线或固定按钮高度。带标题的半模态沿用同一背景合同，深浅色均保留系统材质。图片插件和模型管理仍是独立第二层半模态；全局设置保留原入口。当前采用依据为 CURRENT_STATUS 的 READER_SETTINGS_TABBED_SHEET。

- 亮度与滤镜只属于显示层：全局和阅读中入口共用 ReaderPreferencesStore 的配置，滑杆预览是临时内存状态，松手沿原有序偏好提交；不进入按书模式覆盖。窗口亮度由宿主根生命周期统一持有并恢复进入前的窗口值，负亮度沿参考使用最低亮度加暗层，不改系统亮度设置。灰度、反色与颜色混合只作用于正文图像，不染控制栏、页码或加载提示，也不改原文件、下载、导出、超分／翻译输入和缓存身份。

- 阅读图片的网络预载限制归宿主全局偏好和网络状态；不改用户预载页数，不拦截前台正文请求。本章、跨章和超分／翻译预取共享限制，网络变化更新原会话需求；本地图片处理仍可继续。Shared 与保留的 Legacy 路径均沿此边界，不把网络配置写进公共 Kit。

- 翻译和超分模型完整文件的长度与固定摘要校验由独立 TaskPool 入口执行，设置、下载提交及首次处理共用同一校验；readiness 仍归原模型服务，异步旧结果不能复活已删除路径或覆盖已安装结果。不把 `async` 函数中的同步读盘/摘要当作后台执行，也不为减负删去校验。

- 超分与翻译的原图内容指纹同样在 TaskPool 准备；保持原完整内容摘要和缓存身份，不用路径、时间戳或首段摘要替代。超分在该异步边界之后重核调用方取消及捕获配置，再取派生缓存或认领原生任务；翻译沿原配置 revision 校验后才进入提供方。

- 漫画翻译只在明确的当前页动作或本次阅读主动开启自动翻译后执行，退出后自动翻译关闭。Koma 的翻译配置由独立安全资产串行读写，内容遵守官方每条1024字节限制分块，最后以短索引原子提交，只发布无凭据的 revision；不得读取 NextE 的账户、密钥或库。源文件、章节、目标语言、配置 revision 和当前 Reader 共同限定处理身份，配置改变后旧请求不能再发起提供方调用或覆盖当前页；已开始的调用仍可完成并保留合法缓存，但迟到结果不得发布。唯一主结果是经过身份与文件校验的本地译图，失败保留原图，不能以 OCR 文本、占位图或模拟提供方响应代替实际译图验收。制图与文本提供方沿现有 NextE 处理合同，各自的配置、模型资产和生成缓存留在 Koma 宿主；不在公共 Kit 内放服务、账户或持久设置。 ImageKit `readPixelsToBuffer` 导出不含内存对齐填充字节，RGBA8888紧密buffer的行距使用width×4，不沿用分配内存的ImageInfo.stride；保模型/后端、原处理路径与性能预算，依据为CURRENT_STATUS原NEXTE项及[官方PixelMap合同](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/arkts-apis-image-pixelmap)。

### 诊断日志

- 日志热路径的重复脱敏仅可复用 `DiagnosticsRedactor` 自己创建、字段仍未变化且再次脱敏不会变化的私有安全快照，命中也返回新副本，不向调用方暴露缓存快照。一次处理不稳定的文本、普通对象、外部冻结对象、复制或已变更对象仍须完整脱敏。保留原规则、各输出渠道、文件留存及磁盘失败回退，不把性能优化变成信任调用方或删除诊断。

- 新日志持久文件、分享、保存用已采用的 .log，Picker 沿描述|后缀合同。旧 .txt 历史保持文件名、可读和留存，不重写旧日志；后缀纠正不授权改日志页布局、开关或级别。
