# Koma 执行规则

本文件规定如何交付，不维护当前进度。AGENTS.md 只保留跨任务原则和本文件入口；具体产品决定与当前结果归 [CURRENT_STATUS.md](../CURRENT_STATUS.md) 原项，公共实现旁说明技术边界。改变决定时更新原处及失效引用，不把一次纠正追加到所有文档。

## 强制先读：禁止编造记忆与无依据确认

- 每次开始、压缩或交接后，以及回应用户纠正、历史要求或既定决定前，必须先读本节。
- 严禁编造、补齐或冒充记忆。用户当前的纠正可作为当前指令执行，但必须如实说明信息来自当前纠正，不能说成自己记得、早已知道或已经独立核实的历史。
- 只有当前可见原文或实际查证的原始记录支持时，才能声称“你之前要求过”“我记得”“已经确认”。摘要、交接、记忆页、工作单和当前实现只能提供线索，不能冒充原始对话或查证结果；日期、原话、因果和授权范围均不得猜补。
- 不知道就明确说不知道，未查证就明确说未查证。禁止为了附和、安抚或表现得记住了而使用无依据的确定语气；发现先前无依据确认，必须撤回并澄清真实信息来源，不能继续把它写成历史事实。
- 用户禁止查询时立即遵守，不检索、不凭空补造答案。仅回答当前已知内容，不能把“不许查”变成虚构记忆的理由。

## 指令优先级与工作责任

- 用户最新明确要求优先于旧计划、自动唤醒、摘要和历史文档；已确认的产品行为及禁止项持续有效，除非用户明确改变。新任务不自动推翻既定决定。
- 当前任务以可用的用户结果为目标。主执行者主动负责完成任务所必需的入口、关联页面、公共状态、失败恢复和调用方，不以“用户没有逐项点名”为理由漏做；也不以主动补齐为理由改变已确认产品取舍。
- 设计与实现的错误由执行者承担。沟通直接说明问题、改动和结果；限制只在影响用户判断或行动时说明，不在每个结果后附带免责话，不拿用户曾经批准、测试通过或工具限制推卸错误。具体未验范围持续记在原工作单，避免在对话里反复堆砌。
- 对已有授权范围内的必要工作直接执行。只有确实需要改变既定产品行为、扩大权限或作不可逆操作时才提问；先完成可独立完成的调查和准备，说明精确差异。不得反复请求已有授权，或把方案责任转交用户。
- 用户插入问题或纠正不自动终止原任务；用户要求暂停、只分析或先整顿工作方式时，停止相冲突的操作，自动唤醒不得越过这一要求。
- [CURRENT_STATUS.md](../CURRENT_STATUS.md) 是 App/中文源唯一当前队列；共享 Reader 用已指定的跨宿主工作单。先接续实际 owner，单项缺条件不影响其它安全且已授权事项；不能从少数摘要得出全部无事可做。
- 支撑脚本、文档、测试和构建只服务当前交付。不得用整理状态、增加测试、局部提交或回答问题代替产品修复，也不得为维持忙碌重开已接受路径。
- 只在当前目标完成、用户明确暂停/替换，或完整剩余范围逐项有具体阻碍且无安全替代时结束。未完成时不得仅宣告下一步后停工。

### CURRENT_STATUS.md 是给用户看的 bug 进度页

- 读者是用户，不是接手代理。每项回答四件事：用户何时报的、已经过了多久、现在做到哪一步、还差什么或卡在哪里。完整计数始终以 snapshot 的项数和 kind 现算，禁止手写“N 项未完成”。
- 首页正文只写当前结论：正在做什么、是否卡在设备或权限、下一步。禁止把 CI 编号、release/tag、commit hash、字节数、文件数、哈希、逐个测试通过和日志路径放进正文；这些只进原项证据字段、work order 原文或 archive。
- 每项必须保留提出时间及来源；原始时间查不到就显示“原始时间未核实”，不得用登记时刻冒充用户提出时间，也不得用“工时未知”一段长句填空。已经验收或搁置的项不再占首页篇幅，但保留可切换查看。
- 工作记录、交接和过程时间线写进 archive 或原项字段；进度页只保留能回答“我还有多少问题、等了多久、推进到哪”的信息。更新进度时不得重写、压缩或删除既有条目、owner、边界及证据。
- 每次实质推进（完成一次修复、完成一次设备验证、确认一次失败、改变一次结论或恢复一次设备状态）必须同时更新对应事项的 status/result/remaining，并在 snapshot.timeline 追加一条带时间、标题、结果边界的记录，且更新 updatedAt。只改事项字段、不追加 timeline，视为没有向用户报告本次推进。
- 改动进度页前先读本页；页面版式变更须保留现有筛选用法，不得为了排版重做信息结构，也不得未经读回验证就交付。

## 修改前：先建立依据，不能由实现倒推正确性

- 修改既有界面、组件或参数前，必须先查组件及受影响调用方的修改历史：读取当前未提交差异，按文件和符号执行适用的 `git log --follow`、`git log -S/-G`，并用 `git show` 或 `git blame` 定位引入、调整、撤销该行为的记录；再核对原始用户要求、相关调查分析、决策取代关系、验收和已拒绝方案。不能只读当前数值或公共组件默认值就提出修改。
- Git 历史不覆盖全部开发决策。未提交 WIP、归档记录及原始对话中的有效决定同样必须核对；未提交、压缩、交接或归档都不使决定失效。未查清来源就明确未知并保留现状，不能把查不到当成可以重做。
- 界面评估先证明具体用户任务或使用状态存在问题，再决定是否改动及选用组件。不同于默认值、使用自绘组合、与其他页不相同，均不能单独证明缺陷；禁止为统一模板或参数反复重做已定设计。
- 既定决定只因用户明确改变要求、新的实际反例或具体依赖变化重新审议；必须说明新证据及原决定的理由为何不再成立。拟改动前留下“修改对象/历史来源/原理由/本次重开依据/允许差异”的可查记录；缺依据不得反向立项、修改或交给代理。
- 请求批准不能代替调查与方案责任。向用户提交候选前必须完成上述追溯，主动说明与既定决定的冲突；不得拿小 diff、组件默认值、笼统“规范”或用户点过批准作为无依据方案的免责理由。

- 移植现成功能先读参考实现的完整行为，包括入口、菜单层级、状态归属、默认值、无配置及失败状态、后台处理和返回关系。先完成忠实、可运行的完整路径，再考虑优化；不能只移植处理库后自行拼装产品。
- 复用现有实现及其责任边界，先核所有者、写入/失效、异步回调及全部真实消费者。公共能力不能在多个页面分别维护持久状态或相互矛盾的可用性判断。
- 只做必要的宿主、路由、持久化及平台接口适配。每处参考差异说明实际不兼容点；“更合理”“小 diff”“更适合本项目”都不是自行改设计的依据。适配触及已定产品行为时，先取得该具体差异的允许。
- 架构检查必须改变实施：确定功能属于哪个已有模块、配置作用域和生命周期、哪些现有调用方需要同步修改。不得把孤立新增组件、代码存在或接口连通当成完整接入。

## 实现时：保留产品，完整处理关联影响

**未经用户明确允许，禁止更改样式；修 bug 也不例外。**

- 已确认的正常功能、外观、数据及操作是改动边界。授权修复包含必要关联实现，并非只改用户逐字指出的局部；但圆角问题不授权改尺寸，按钮问题不授权删入口，局部问题不授权重做公共 shell。
- 用户已明确采用的更正按该允许直接实施，不再以“样式需批准”为由保留已被明确要求纠正的错误。未允许的差异仍须先说明和取得决定。
- 全局长期配置、当前会话操作和公共处理能力分别归已有 owner；菜单、设置搜索、路由与能力可用性同步接通。不得摆放无法使用的入口，或让无配置、未选择、加载及失败状态消失在正常状态之外。
- 缓存服务可用首帧：有可用快照时先保留内容和行/图标身份，后台检查后差量发布；不把空白→读缓存→整表重建当作缓存完成。重型 I/O、解析及图像处理不得同步挤入入场动画；检查所有真实消费者，不能只在当前页补一份缓存。
- 预载、原图准备、图像预处理和最终显示是不同阶段。功能需要预处理时必须接入现有准备链，检查预载页也实际消费该能力；当前页处理成功不能证明预处理已覆盖。
- 失败与部分成功必须如实反映已知/未知，保留仍可用结果。恢复只处理对应失败，不重放无关操作、不改设备/服务环境制造通过。
- 原因未知写未知；不靠任意延时、持久状态注入、清数据、改权限/网络或参数试错消除现象。
- 发现方向错误立即停止并撤回不符合边界的差异，保留失败；不得笼统回滚整批 WIP 或删除已确认成果。临时诊断和临时设备状态恢复后读回。

## 验证与收口：先证明用户任务，再考虑测试数量

- 验收依据来自用户要求、原正常行为和已采用参考，必须先于新实现确定。不得改完实现再改测试期望放行；期望确错须有用户决定或真实反例，并留下取代原因。
- 先检查完整普通路径的实际入口、无配置/准备状态、使用过程和返回结果。直接及间接受影响路径都要考虑；公共代码没改、小 diff 或单一消费者通过不证明无影响。
- 少写测试。只保留能执行关键逻辑、失败恢复和必要边界的覆盖；已有覆盖不重复。禁止仅匹配源码字符串、字段写法、组件嵌套或截图数量的检查，也不新增 UI 正则、hook、命令拦截或自造门禁来代替判断。
- 测试证明其实际执行的逻辑；编译/CI证明构建；安装证明包已安装。它们不能判断产品层级是否合理，也不能替代真实使用、图像可见、预载处理、转场连续性或外部服务结果。
- 界面和交互用当前签名包走普通入口，顺序观察完整动作和返回，先找画面异常再对齐日志。转场/滚动看连续原片；不得挑稳定帧、只看缓存终点或以布局节点存在冒渲染成功。
- 核对前台 App、实际包、设备型号、方向/折叠及窗口；只比较同状态、同 viewport。任一可见反例使相关结论失效，脚本/日志/代理 PASS 不得抵消。
- 只通过具名版本、设备和路径。未验证写未验证；真实进程死亡与同进程回滚分开，未配置外部服务的功能不能冒真实调用通过。已接受路径按其范围冻结，只由新反馈、真实反例或具体依赖变化重开。
- 提交前审精确 diff、权限范围及关联消费者；按有效授权分组提交和同步。构建、安装、验收、提交、推送、发布分别记事实，不自设重复批准门，也不把未授权发布扩大成不提交有效工作。

## 文档与沟通：修改事实时维护原处

- 同一产品决定只在既有权威位置维护，其他文档用链接；实现旁保留为什么及何时可改，进度留原工作单。历史用于查证，不自动派工。变更行为时必须同时纠正冲突/失效引用，不能把维护责任留给用户定期全局排查。
- 默认阅读链中的技术/开发文档只描述当前有效合同、职责和状态；历史修改与决策取代经过另存，当前文档不链接历史档，明确查证历史时再按需读取。AGENTS.md 不存具体功能需求、临时状态、设备地址、实现参数、证据编号或待办清单。模块规则按当前工作选读；不得把本轮方案、验收状态和长期原则揉成一条永久禁令。
- 批评、错误表现、候选、采用决定和验证结果明确分开；登记前核原话方向，不能把用户投诉的错误写成应保留的边界。规则变更本身也按原意审 diff。
- 沟通给出新发现、实际变化、证据边界及仍未知处。回答“为什么”须解释实际判断错误，回答“怎么改”须给具体执行方式；不得把用户的话扩写成自己的发现，也不以认错、保证或测试数量替代行动。
- 当前结果、剩余动作及 owner 只更新原工作单；交接保留原目标、限制、失败、WIP、设备恢复和下一未完成动作。下一轮须接续这些事实，不能凭压缩/换轮次撤销要求。文字记录不等于执行保证。
- 更新日志按“新增／修复／优化／已知问题”分类，不把未解决或未验证写成已修复。

## 权限、工作区、设备和数据

- 未经用户明确允许不得创建任何 worktree；保护 WIP、并行、隔离验证或打包都不是许可，不能用额外 clone、源码副本或子代理规避。仅在获准用途内使用已允许的 worktree，完成后合回原主仓并退出。
- 不默认建子代理；只按用户明确允许范围分工，复用现有 owner，不重复派同一项。主执行者审真实 diff 和证据，设备串行操作。保护用户 WIP、数据和素材，不广泛 add/reset/clean。
- HarmonyOS 源码、构建、设备操作先按 `harmony-mandatory-preflight` 读相应开发/设备技能；同任务流程可复用，不能因压缩全量重复预检制造等待。不确定 API 查官方合同、版本及权限。
- 设备、截图、日志、UI 操作还必须读 `harmony-run-device-diagnostics`，开始前说明选用技能和原因。用户选定设备后用完整 target 解析并经租约执行；状态和取证统一走项目 checked manifest，直接租约 HDC 仅限发现/重连、`shell echo`、启动读回和文件接收。
- 锁屏是流程内状态，不是阻塞理由：唤醒、在非通知区域滑开、解锁后写超时并读回要放在同一清单连续完成，再进入 UI。不得因为锁屏停工、换设备或改去启停模拟器；模拟器不得替代用户指定的真机，其结果不写入验收。
- HDC 及任何可能调用 HDC 的 helper（包括只读/dry-run）必须在沙盒外执行。实时解析当前授权 target 并持有效租约；不能用旧地址、端口、租约或沙盒连接错误判断设备离线。
- 设备号只是故障线索，不扩大授权。允许日志不等于允许点击、启动/安装、切章、清缓存、改设置或写数据；已有明确测试机及范围授权持续有效，范围不明先查本地。禁止操作的设备、用户搁置项不得复活。
- 状态操作复用项目 checked manifest 和语义路径；正常控制前建立唤醒/超时等技能要求。动作注入不证明跳转。返回失败先保留当前证据并核前台/路由，不连续 Back 猜页面，禁止越出授权 App 后继续通用点击。
- 不自行启停/重启模拟器，不清用户数据/缓存。失败也必须独立执行设备恢复和释租，不能因截图、快照或页面断言失败跳过清理；读回最终状态。
- 签名沿当前已验证的本地构建配置和该 bundle 的既有 profile，不生成/替换证书凑安装。环境文件、配置路径可能变化，先核实际存在性；旧文档固定路径不冒当前事实。签名秘密不进源码或日志，macOS 不用 Linux dev.sh。替换包前核包身份与既有签名，不能清数据绕过冲突。
- 首版产品范围与对外边界以已采用产品决定为准；不内置源或源市场，不宣传全网/免费/聚合。普通界面不出现内部 QA/debug/path；不复制 Aidoku/Homo 代码或资源。
- 本地移出只按 LOCAL_ARCHIVE/LOCAL_FOLDER 既有边界，不删外部原文件或广泛缓存；mock/undefined 不删。删除日志不含书名、原路径或原始 ID。

## 模块边界（仅处理对应工作时选读）

下列保留已确认行为及技术约束，不维护版本、owner 或待办；当前状态与变更依据仍见原工作单。不能由这里的旧验收范围恢复任务。

### 导航与界面

- 兼容低版本系统时，能力判断必须先于新 API 命名空间、枚举和构造器的实际求值；把判断放在接收新枚举实参的函数内部不能保护调用方。保留已采用的高版本效果和低版本原有回退。
- 根 HdsTabs 拥有底部导航；子页不重复根标题，不按固定底栏高度缩小窗口。公共导航/安全区须有该层因果证据，再检查根页和受影响子页。
- 现有 Koma 外观与 HDS 控件按已确认边界保留；参考应用提供已采用的行为/结构，不自动授权全面换肤。源图标优先真实官网身份；素材不擅加底板、阴影、遮罩。黑色主体深色辨识不足可沿已采用固定白底，保原形及黑色；统一圆角容器不由素材处理擅改。来源争议先查，不称错误站点为官方。

- 章节列表的按压反馈复用 `ConciseListRow` 的 HDS 行内缩圆角面；外层 `ListItem`、分组卡片及其留白不负责反馈。下载按钮仍是独立动作，不能因复用行组件触发阅读。分割线由原生列表分组绘制，不放在每行卡片裁切边界上。

### 书源、验证和缓存

- 漫画160普通网页的鸿蒙识别兼容只属于当前 Web 实例：初始地址须为已核的 www/m 两个 HTTPS origin、无验证会话，且默认 UA 同时含 OpenHarmony/Mobile、没有 Android/iOS 标识，才在保留全部字段后追加 Android 标记。依据与原详情实测保留在 CURRENT_STATUS 的 SOURCE_WEB_SESSION；不扩大到全局 UA、源 HTTP、验证 sheet、缩放或导航拦截。站点两端都已正确识别 OpenHarmony 的新证据出现后才重新审议此兼容，不能因通用封装重构丢掉或全局套用。

- 统一搜索遇到源明确返回的验证/登录要求时，按源独立认领，并串行复用现有验证半模态；其它源继续返回结果。依据为 CURRENT_STATUS 的 SOURCE_WEB_SESSION 中当前已采用要求。通过后只重试该源原请求一次；关闭、再次挑战、切换查询/筛选或离开页面不得循环弹出或重放旧请求。源包身份、设置版本及当前页面共同决定回调是否有效；保留单源验证的 Cookie/权限/UA 和样式边界。原生验证得到的单次响应只由精确匹配的原请求消费，无关并发请求不能清走；取消对应会话时仍清理它。站点验证后跳到同源其它地址404、但已有明确 clearance 时，可在原认领仍有效时探测原GET一次；404与Cookie都不能直接授予成功，只有原GET真实2xx且无挑战才能回流，失败保留手动操作。原地址的主请求错误、其它错误和跨源地址仍保持原拦截边界。不得因全量搜索汇总迟到覆盖已验证源的新结果。

- UI内存状态键须遵守AppStorageV2平台字符约束，并与持久偏好键分开核对。语言状态的具体边界见 `state/LanguageState.ets` 旁注及 `i18n/LanguageSettings.ets`：消除连接开销不能删除locale响应式依赖、改语言偏好或破坏启动恢复。

- 已收藏源漫画的详情归现有 Comic/Library 持久域；进程内详情缓存只补充热快照，不另存一份章节表、正文临时地址或源凭据。已有详情先呈现，后台重验不能重置加载态或自动弹出验证；显式刷新保留原反馈与验证恢复。更新以实时书库对象为基准，保留分类、章节页表和阅读进度；相同结果不重复写盘或发布书架变化。扩展持久字段时同步所有复制、分类变更和书库更新路径，不能在下一次更新时丢掉它们。

- 已安装源的展示排序须保留原本地化名称、比较器、同名ID顺序和DTO身份；单次排序内可先逐源解析名称，不能在每次比较中重复校验元数据，也不能把名称缓存跨locale或源变更保留。Browse模型刷新时，仅完整展示DTO值相等才复用本模型的原行对象，仍发布新有序数组；字段改变、移除和失败恢复沿原合同，请求及源包有效性继续读实时Registry，不由展示对象决定。减少重复解析或行输入重建不能代替普通路径的性能验证。

- Browse 的源展示投影同时受所选页签与根导航实际可见性约束；被源管理等页面覆盖时保留当前行，返回可见后消费最新 Registry revision 一次，未变更不重建。远程服务可用性的页签激活刷新仍由原 owner 独立处理，不因延后源展示而漏掉或增加该请求。

- 源可用性核验按用户要求覆盖全部85源，须对照固定版本Mihon/Keiyoushi真实实现的设置项、默认值、实际消费及能力/导出；静态cap、schema通过或参考文件取回不等功能完整。网页入口仅在已有合法主页地址时显示，源生产包校验主页必填；未知/空设置schema不显示入口，单源schema失败不得污染全局已保存设置状态；确有存储读取失败时保留有效入口并显示具体读取阶段，不得以“设置验证失败”等泛化提示代替处理。源设置迁移须核真实消费，敏感cookies/userId/token不得因有导出就开放普通明文持久。当前实现/验收状态以CURRENT_STATUS原源条目为准，不以本规则冒WIP已交付。

- 多地址源更新检查只部分成功时，保留已确认的更新，未查全的源不得新判为最新或未找到；失败原因归现有地址行，单地址重载成功只清该地址原因，不冒全量检查完成。当前已采用的具体文字和范围以CURRENT_STATUS的SOURCE_INDEX_CACHE_REVALIDATE为唯一依据；全部成功和全部失败的原合同保持。普通源包行按当前采用范围展示身份信息和可用操作，不逐行重复全局检查状态；渲染避免每行重复扫描全部源并记录交叉依赖；帧缓存只用于渲染，更新完成直接消费本次返回的DTO，异步设置回写校验当前packages的对象身份及原revision，不能因性能修复读到上一帧结果或丢弃本次有效设置。批量更新的每源完成也复用单包投影，保留最终完整核对及原禁用状态、失败/跳过计数和顺序。普通本地归档和索引安装共用同一串行队列；归档身份尚未知时用不含文件URI的私有任务身份，不全局禁用无关源按钮，删除和重复选择器的独占保护保持。 管理页可用快照由页面外进程级owner保留；启动仅本地预热，实际进入manager的intent只触发一次后台revalidate，显式检查保留。页面首帧不读盘解析或自动清空；相同DTO/图标身份不重发，完整结果就绪后差量发布。备份恢复或源身份失效后，旧draft不得继续请求后续地址或发布。

- 已存源章节页表绑定生成它的源设置摘要，并随章节持久化及目录合并保留。设置相同时复用；设置变化后只在实际需要该章时重新取页，成功后替换页表及摘要，失败保留原页表且不得标成新设置。空设置兼容旧页表；不清图片缓存、不改离线下载清单或阅读进度，不把此修复改成每次入场全量刷新。摘要取自实际get_pages请求快照，当前设置变化后迟到结果不能提交。

### Reader 迁移与翻译

- LLM 提供方按源身份管理 API 配置或 Codex 登录，消费者绑定源与模型，不在源删除后隐式改用其他账户。消费者表单只保存绑定与翻译选项，不覆盖源登记表；管理页的增删通过原 revision 同步到保留的页面。OAuth 凭据沿 Koma 原子安全写入 owner 保存；自动轮换必须核旧凭据且不推进用户配置 revision，手动登录/退出才使旧处理配置失效。界面只保连接状态与公开账户信息；用量缓存按源和账户隔离，不保存凭据、不进入备份，旧页面或已删除源的迟到结果不能回写。模型列表取所选提供方的实际目录，不自造共用模型白名单。

- 阅读控制栏的单双页按钮只控制单/双页，方向按钮提供从左到右、从右到左、纵向分页和连续滚动四个互斥方式；阅读设置与全局阅读设置复用 `ReaderDirectionMenuItems`，设置命令经 `readerControlDirectionSelection` 成对更新模式和方向。连续滚动时单双页操作沿控制栏的禁用状态；水平顺序在纵向方式下仍保留为休眠值。不得另写一份混入连续滚动的单双页菜单，或把连续滚动降成“从上到下”的别名。当前依据为 CURRENT_STATUS 原 READER_SETTINGS_PLACEMENT 项。

- NextE 阅读能力迁移沿用户已采用的现有阅读设置和更多入口，具体允许差异以 CURRENT_STATUS 的 NEXTE_READER_FEATURE_MIGRATION 为唯一依据。裁边强度与超分配置复用 ReaderPreferencesStore 的有序写入、备份与 runtime 发布；处理器消费已发布配置，不能另立持久 owner。原去白边默认 false、超分默认关闭；选择或下载模型不自动开启，模型资产须校验后才可交原生处理。原图下载、预载、导出和进度仍由原宿主负责，处理失败保留原图；检测/增强结果只能经现有 Kit 的 crop/variant 合同进入画面，不改 Kit、目录顺序、阅读模式或既定转场来适配功能。

- Reader 即时控制与全局长期配置分责；具体采用入口、分组和日志归属见 CURRENT_STATUS 的 NEXTE_READER_FEATURE_MIGRATION。增强模型未选/不可用仍保留可见开关；模型选择与模型文件管理沿 NextE 原职责，不能自行合并成下载选择菜单。各入口消费同一配置及能力状态。

- 翻译和超分模型完整文件的长度与固定摘要校验由独立 TaskPool 入口执行，设置、下载提交及首次处理共用同一校验；readiness 仍归原模型服务，异步旧结果不能复活已删除路径或覆盖已安装结果。不把 `async` 函数中的同步读盘/摘要当作后台执行，也不为减负删去校验。

- 超分与翻译的原图内容指纹同样在 TaskPool 准备；保持原完整内容摘要和缓存身份，不用路径、时间戳或首段摘要替代。超分在该异步边界之后重核调用方取消及捕获配置，再取派生缓存或认领原生任务；翻译沿原配置 revision 校验后才进入提供方。

- 漫画翻译只在明确的当前页动作或本次阅读主动开启自动翻译后执行，退出后自动翻译关闭。Koma 的翻译配置由独立安全资产串行读写，内容遵守官方每条1024字节限制分块，最后以短索引原子提交，只发布无凭据的 revision；不得读取 NextE 的账户、密钥或库。源文件、章节、目标语言、配置 revision 和当前 Reader 共同限定处理身份，配置改变后旧请求不能再发起提供方调用或覆盖当前页；已开始的调用仍可完成并保留合法缓存，但迟到结果不得发布。唯一主结果是经过身份与文件校验的本地译图，失败保留原图，不能以 OCR 文本、占位图或模拟提供方响应代替实际译图验收。制图与文本提供方沿现有 NextE 处理合同，各自的配置、模型资产和生成缓存留在 Koma 宿主；不在公共 Kit 内放服务、账户或持久设置。 ImageKit `readPixelsToBuffer` 导出不含内存对齐填充字节，RGBA8888紧密buffer的行距使用width×4，不沿用分配内存的ImageInfo.stride；保模型/后端、原处理路径与性能预算，依据为CURRENT_STATUS原NEXTE项及[官方PixelMap合同](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/arkts-apis-image-pixelmap)。

### 诊断日志

- 日志热路径的重复脱敏仅可复用 `DiagnosticsRedactor` 自己创建、字段仍未变化且再次脱敏不会变化的私有安全快照，命中也返回新副本，不向调用方暴露缓存快照。一次处理不稳定的文本、普通对象、外部冻结对象、复制或已变更对象仍须完整脱敏。保留原规则、各输出渠道、文件留存及磁盘失败回退，不把性能优化变成信任调用方或删除诊断。

- 新日志持久文件、分享、保存用已采用的 .log，Picker 沿描述|后缀合同。旧 .txt 历史保持文件名、可读和留存，不重写旧日志；后缀纠正不授权改日志页布局、开关或级别。
