# Reader 迁移参考与执行边界

本文件规定当前 Reader 的参考迁移方式。当前共享职责见 [reader-kit consumer contract](../../third_party/reader-kit/README.md#consumer-contract)，具体采用范围、差异和状态见 [CURRENT_STATUS.md](../CURRENT_STATUS.md) 原项，通用执行/验收规则见 [koma-rules.md](koma-rules.md)。

## 共享仓库与依赖同步

- 共享代码在 Koma 同级的独立 `reader-kit` 原仓的 `main` 维护。执行 Git 写操作前先核对 `git rev-parse --show-toplevel`、当前分支和 `git remote get-url --push origin`。推送使用原仓配置的 `origin` 和认证方式。遇到 403，先核对实际仓库和推送地址。
- Koma 的 `third_party/reader-kit` 只按提交检出，用于构建和验收。禁止在该子模块内提交、维护或移动开发分支、推送，也不得改用其他远端或身份尝试推送。先从独立原仓 `/Users/honjow/git/reader-kit` 的 `main` 和它配置的 `origin`（`git@github-3003h:erosTeam/reader-kit.git`）推送，读回远端，确认 Koma 的公共依赖地址能检出该提交，再更新 Koma 的 gitlink。遇到 403 必须停止并核对原仓与认证，不得换身份重试。
- Koma 的模块配置和 OHPM 从子模块读取依赖。CI 先递归检出 gitlink，再同步共享远端 `main` 并记录实际构建使用的 SHA。即使后续有同步步骤，初始 gitlink 也必须在公共远端可取。

## 参考如何使用

- 修改一个已有能力时，先读 NextE 对应的完整实现及调用方，核菜单层级、状态 owner、默认值、无配置/失败、后台准备和返回后的同步，再适配 Koma。不能只取算法库并自行设计其余产品。
- 参考源按实际文件/符号查找，不固定源码行数或旧快照参数。主要入口包括 NextE 的 ReaderPage、ReaderSettingsPage、ReaderSuperResolutionModelsPage 和 ComicTranslationSettingsPage；引用当前任务实际读取的版本，不把路径存在当成已核行为。
- 已采用行为和结构直接沿用；仅调整必要宿主/平台接口。差异写清具体不兼容点及原取舍，涉及已确认产品行为时取得该差异的允许。不能用抽象的“更合理”另做一套。
- 当前 Koma 原生外观与共享 Reader 边界继续有效。参考范围不自动授权对现有宿主全面换肤、替换导航或改公共 Kit。
- 当前用户要求迁移的能力必须完整接入。功能范围由有效需求决定，不能因参考中的宿主专属差异省略通用能力。

## 公共职责与接入

- Koma 现有会话、页面源、偏好、点击区域几何和持久化继续由原 owner 负责；共享 Kit 只按公共合同消费。不得为单个入口建立第二套偏好、缓存或导航状态。
- 分页音量键沿用已有页序、动画开关和原生 Swiper。为缓解触摸空闲时的组件限帧，Koma 宿主仅在启用翻页动画且分页命令被接纳时短时申请 NativeVSync 帧率，翻页结束、阅读器暂停或关闭时撤销。验证记录见[当前工作单](../CURRENT_STATUS.md)第 317 项。
- 自动分页是显式选择，由共享 Kit 根据实际阅读区域和源页顺序分组。未知尺寸保留原来的页位，整张宽页校正前段对页，方页、宽页和用户指定的单页独立显示。导航期间延后应用分组变化，已经显示且仍兼容的双页保留配对。配对仅使用已有尺寸与页序，不要求下载、扫描或解码额外图片。翻页、续读和进度继续使用原始章节与页码。屏幕方向由宿主管理阅读期间的窗口覆盖，离开时恢复原窗口策略。
- 处理结果必须进入真实页面准备及显示链；同时核被使用的预载消费者，不能用当前页单次成功代替预处理。失败保持原图、原进度及原有恢复路径。
- 正文图片的下载进度由宿主网络层提供实际字节数，预载与前台读取共享在途进度。共享 Kit 沿用既有加载反馈，响应大小未知时使用循环加载，已缓存文件直接用于显示。下载进度只描述网络收取，不代表图片已经写入缓存或完成解码。
- 正文流的有效长度与接收块使用同一字节口径时，从响应头回报起点，按收到的数据块推进。编码或分块传输沿用网络层配对的字节计数。起点和第一次增长直接发布，节流期间只保留最新进度并在本段结束后补发。正文成功收完后回报终点字节数，由共享 Kit 改用已有的加载、准备反馈，图片在解码就绪时立即显示。共享反馈的行为依据见 [reader-kit Consumer contract](../../third_party/reader-kit/README.md#consumer-contract)。
- 正文成功响应已读出图头尺寸时，负责该次下载的调用复用这个尺寸。命中缓存、加入其他下载或图头不完整时，仍从最终文件探测尺寸。尺寸通知沿用原来的请求和来源有效性检查。
- 条漫的单图行在当前请求、进度、解码和几何输入相同的情况下复用渲染快照，避免其他短图的加载回执重复刷新本行。请求或显示输入有变化时立即发布本行更新，进场交接、替换保留图和失败处理沿用原有快照边界。
- 文件格式兼容由 Koma 展示准备处理，正文、缩略图、裁切和增强共用既有缓存。先使用 ImageKit 解码原文件。设备解码失败时，静态 8-bit AVIF 可经备用解码生成 PNG 展示件，支持 sRGB 原图及可转换为 sRGB 的灰阶或 RGB ICC。手动重试重新准备展示图，同样的原图字节也可修复损坏的 PNG 缓存。保存、分享、离线下载及导出继续保留原图字节。
- Koma 明确开启分页解码优化，普通倍率按显示区域解码，放大使用当前图片的原分辨率。超分结果已有的像素尺寸随图片传给分页组件，用于首次解码，页码和自动配对继续使用源页信息。共享默认值沿用宿主原解码策略。清晰度切换沿用同一个图像节点，在新图就绪时替换像素，保存和分享继续使用原文件。文件预载独立于原生解码窗口。
- 有实际像素尺寸的条漫超分图也通过同一原生 Image 在普通倍率按显示面积解码，放大时切到完整超分像素。显示解码尺寸沿用当前行的裁边与旋转几何，行高仍由源图和既有裁边逻辑决定。超分文件、原图和保存分享的资源归属保持各自原有合同。
- 系统超分可共享的输出 PixelMap 在同一后台任务完成 RGBA 归一化和 JPEG 编码。无法共享时，现有原生 PixelMap 向一次性 RGBA 缓冲读取像素，缓冲转移给同一编码任务，归一化后的 PixelMap 和编码器都在后台释放。会话仍在滚动稳定后派发，只有结果归属有效、临时文件完整时才发布。
- 超分结果发布后的缓存扫描、排序和淘汰在同一后台任务执行，仍按原容量、数量和最近访问时间淘汰，并保留本次文件。单处理槽等待清理结束，查看缓存大小不会清理在途临时文件。
- 超分临时切换复用同页已有的原图和增强文件，准备与显示交接沿用 [Reader Kit 文件租约约定](../../third_party/reader-kit/README.md#consumer-contract)。宿主队列跟随当前页升降优先级，系统超分已进入一次原生调用时，在其返回后让出槽位。
- 在线历史已有目标章时，先准备该章正文。完整目录由阅读器在后台补齐，并同时更新手动选章和已验证的连读顺序。书源正文计划仍按正常规则更新，续读前的进度冲突检查仍由同步模块负责。
- 阅读器缩略图按实际显示像素解码，最多取裁剪区域的原尺寸。使用缩略图栏的槽位尺寸换算，避免高密度屏放大低清预览，也避免用整页原图代替缩略图。
- 分页滑动中的位置变化不触发图片尺寸、缩放约束或进场矩形的重复测量。常规像素布局监听尺寸，进行中的进场动画另测实际位置。普通翻页只将变动的章节位置和同步待发送记录交给后台，与现有阅读文件合并后原子替换。同步回执也按变更行提交并核对写入前的版本，需传完整同步文档时用序列化文本，避免任务入队时在 UI 线程深拷贝。历史编辑、备份恢复与离开阅读的持久化沿用现有边界。
- 完整 WebDAV 同步的计划编解码、回执文档编码仍按现有事务边界提交。阅读手势及松手后的惯性时段，这些留在 UI 线程的分批操作使用更短的时间片和有间隔的让出，避免零延时任务连续排满多个 VSync。惯性时段沿用既有缓存等待窗口，恢复时继续校验连接和状态版本。窗口结束后沿用正常同步预算。
- 自动阅读同步在生成快照的同一后台任务内读取持久化书架、阅读进度和投影文件，避免将原始文本交回 UI 线程再传给后台。现有快照版本计算、恢复证明和提交校验沿用原有规则。
- 保存和分享在用户触发时捕获当前原页。翻页期间只为已发起的操作核验目标，以便换页或离开时及时取消旧准备。系统面板已经打开时继续沿用它自己持有的资源。
- 本地文件夹的相邻章节按导入器已建立的文件顺序准备，和原相邻章导航共用目录及页数预算；不要求它伪造书源的版本分组元数据。在线书源仍须提供已核续读序列，不以完整手动目录代替；本地预载不改 Legacy 的自动切章许可。
- 在线自然跨章和跨章预载共用 `ReaderChapterSequence`。完整原源目录的阅读位置生成规则见[书源 ABI](../source-runtime-abi.md#网页会话与章序)。旧库缺原源位置时在阅读器后台补齐，保当前章和已显示的页。详情展示排序与 LTR/RTL 不改变阅读关系。
- 接近章末即可准备下一章页表，图片预载沿用设置的页数。连续阅读为已确认的下一章保留至少一屏的加载区域，手动拖动和惯性都可以在页表返回前滚过上一章末页。页表返回时沿用首图的列表项标识继续排版，已停在加载区域的位置在图片尺寸更新后保留，失败可原地重试。加载区域没有正文页或阅读进度，已显示的正文仍由原观测路径写入进度。
- 完整接入包括普通入口、配置作用域、菜单/搜索、能力可用性、无配置状态、保存恢复、返回同步和旧请求失效；不能凭一个设置 sheet 或一段 provider 链宣告整项完成。
- 具体当前配置归属、模型管理和翻译数据保护约束只维护在执行规则的模块边界与对应公共实现旁，本文件不复制易变的入口、默认值、参数或验收状态。

## 界面与行为边界

- 不恢复已被拒绝的 Koma 阅读器方案；既定禁止项不因重构或换轮次失效。
- QuickSettingsPanel 浮层卡片、KomaSegmentedControl 替代方案、暖棕 pill，以及抢占阅读区手势的透明层/扩大响应区，不作为迁移捷径。
- 阅读器设置半模态在应用运行期间保留上次选中的分段。再次打开到滤镜时恢复实时预览，关闭后交还阅读界面。
- 不能通过删除设置入口、关闭正常功能、改阅读顺序或修改数据使缺陷消失。当前确有必要差异仍走用户决定，不能拿本文件推翻已采用行为。

## 如何判定这次迁移完成

- 先用已采用参考和原正常行为确定当前改动应保留的结果，再实现和验证；不能从新代码倒推测试期望。所有直接/间接受影响消费者都须考虑，不以文件未改排除。
- 普通入口进入后，观察功能准备、实际使用、无配置/失败及返回状态；变更需要持久化时核真实恢复。只验与本次变化相关的路径，不重跑已接受矩阵填充测试数量。
- UI/图像/转场用当前安装签名包及匹配设备状态观察完整过程。布局节点、模拟响应、成功终点图和构建/CI不能冒真实画面或完整路径通过。
- 复用现有语义场景/设备协议；禁止源码字符串和组件嵌套断言、自造 UI 门禁或无效重复覆盖。必要真实路径验证与通用测试边界以 koma-rules 为准。
- 当前授权设备由实时发现和租约决定，不使用文档中的固定 IP；包、构建模式和签名按当前交付要求核实，不假定 debug 构建即可交付。保留原数据，失败独立恢复临时状态。
- 构建、安装、普通路径、验收、提交和同步分别据实记在原工作单。未验证或存在相关反例时整项未完成；不得因为已编译、已有大量用例或局部提交而关单。
