# 书源运行时接口设计评审

目标是让书源可以独立适配尚未出现的站点流程。宿主统一管理网络、授权、资源和原生界面。书源决定请求顺序、分页、格式、站点状态和算法。本文为设计稿，现行协议以 [源包与运行 ABI](source-runtime-abi.md) 为准。

## 保持现有入口

继续使用 `get_listings`、`get_settings`、`search`、`get_manga`、`get_chapters`、`get_pages`、`get_image_request` 等入口。宿主消费稳定的作品、章节、图片和设置描述。一次操作内，WASM 可以按站点流程串行或并行使用已有底层调用。SDK 把分页、格式解析、签名校验、数据变换和翻译逻辑编进源包，随源包发布。

现有请求信封、WASM 导入和 `hostFeatures` 继续作为兼容边界。优先在原调用中加入可选参数或返回类型。一个新参数能否复用旧接口，按它是否使用相同的授权、结果类型和生命周期判断。新语义只有在这些边界无法表达时才需要独立能力。

## 作品和目录的结果合同

以下四组描述的是书源执行过程中可以调用的底层能力。执行完成后，App 还要正确消费作品、章节和翻页结果。两层各有自己的合同。

以目录为例，章节至少有三种独立信息：

- **身份**用于书架、历史、续读与同步。源提供稳定 ID。显示标题、目录位置或站点分组变化时，沿用原 ID 或已有映射。
- **显示**使用站点的目录顺序和可选的真实话数。标题无法取出话数时保留原文，App 仍可以按源顺序完整显示目录。
- **续章**描述同一阅读分组内的相邻关系，供上一章、下一章和预载共用。源明确声明可自动续章的位置、只可手动打开的项目及多版本边界。对于旧源未声明的目录，宿主沿用已验证的目录方向兜底，同时保留无话数章节的位置。

完整与分页目录沿用现有 `get_chapters` 结果和游标语义。站点把目录拆成多段时，源提供已核实的分组及顺序。宿主在已加载边界保持查询身份和游标，继续读取该目录，用户选择的显示排序独立保留。验收应覆盖目录中段、跨分页边界和无话数条目，连同真实章节详情、下一章和预载一起检查。

「开始阅读」在有有效进度时回到原章节。没有进度时，用已确认的顺序找最早未读项。用户选用其它排序依据时，阅读器在同一已确认组内按该依据正向读，界面正反序单独处理。多版本的续章位置只能各自在组内比较，具体规则写在现有 ABI 的[章序部分](source-runtime-abi.md#网页会话与章序)。

## 四处可组合的边界

| 现有入口 | 扩展方式 | 由书源决定 |
| --- | --- | --- |
| 设置描述 | `get_settings` 增加可选 `args.locale`。SDK 统一匹配语言，接受源作者指定的回退语言。 | 字段标题、说明、占位文案、选项、动态可见条件。 |
| HTTP | 在现有 `http_request` 中统一请求匹配和响应类型，保留状态码、最终 URL 和允许提供的响应元数据。沿用文本返回，增加有界字节正文引用。 | 请求方法、地址、正文、公开协议字段、解析和相互依赖的请求顺序。 |
| 用户交互与会话 | 复用官网验证、网页登录和原生凭据表单。使用统一的待交互结果、完成状态和请求恢复规则。 | 哪一步需要交互、使用哪个已声明的原站入口、完成后继续哪个站点步骤。 |
| 图片与二进制处理 | 通用协议数据交给源 WASM，正文图片沿用包内处理器的字节和像素两阶段。 | 格式、分段、还原和兼容旧站点数据的算法。 |

### 设置语言

宿主传入调用开始时的实际界面语言。SDK 按完整语言标签、语言与字形、通用语言、书源指定的回退语言查找该条文案。中文地区标签按现有的简繁映射处理。缺失 `args.locale` 的旧宿主从书源默认回退语言开始查找。沿用设置 ID、选项 value 和已保存的设置。描述缓存按语言区分，切换语言后丢弃迟到的旧描述，保留当前已编辑的值。

### HTTP 正文和请求范围

文本请求继续返回 `bodyText`。需要二进制时，源在 `http_request` 选择 `responseKind: "bodyRef"`，宿主返回状态码和正文引用。SDK 在同一个 `http_request` 导入内调用 `body_read`，传入引用、当前偏移和要读的上限。响应包含 Base64 片段、下一偏移和是否读完。这样每次只有一个有界片段经过 JSON 边界，宿主可以用流或有界缓冲区实现。引用绑定当前源、安装和操作。读完、显式关闭或操作结束时释放，超额、过期、取消或作用域不符返回明确错误。响应元数据按公开字段和授权用途投影，私有会话的完整响应头由宿主管理。

请求范围采用同一组匹配语义，由精确 origin、路径段前缀和可选 HTTP 方法组合。限速和授权可以使用相同的匹配器，各自独立判断。比如限速可以排除一个文件路径，排除规则只影响计数。宿主对每次实际请求和每次跳转重新检查有效范围。已有规则沿原语义解析，旧字段可以在宿主内部归一化，源包迁移时再采用通用表达。

### 交互后恢复

现有 `challenge_required` 和 `auth_required` 归入同一类待交互结果。需要恢复的操作可提供小型不透明续接数据，用于记录可恢复的站点步骤。宿主绑定源、安装身份、原操作和当次交互，结束当前 WASM 调用并释放其网络正文引用。用户完成后，宿主重新调用同一个书源入口，携带原参数、交互结果和相应的会话引用。源根据续接数据选择后续步骤。旧包继续使用原有的完成和重试行为。

用户取消、切换操作、换包或会话撤销后，旧结果失效。会话引用只能给获准的请求使用，权限随用户授权范围逐次核对。源记录已确认完成的步骤，宿主从明确的续接点恢复。读请求沿用现有重试策略。对于有副作用的 POST，源只有在站点提供幂等机制，或能查明前一次没有执行时，才可以再次发送。

### 数据和图片

小型纯算法可作为常规 Rust/WASM 代码随源发布。阅读图片继续经过统一的读取、还原、缓存和下载链路。算法变化走包版本及处理器摘要，宿主无需识别站点的算法名称，也无需为还原后的每种图片格式单独加接口。对超出当前解码器契约的新格式，先判断能否由随包处理器输出宿主已支持的字节或像素。

## 怎样判断还需不需要发 App

- 站点改变 URL、分页、数据格式、授权步骤或还原算法时，先用已有请求、数据和交互语义表达。能表达的改动随源包发布。
- 执行层缺少新的权限、原生交互或资源语义时，才扩展宿主。扩展说明应指出具体缺少的操作，以及适用于其他站点的共同语义。
- 同一份源包可以按 `hostFeatures` 选择新旧路径。旧宿主仍能完整浏览和阅读时，新增可选功能不提高 `minAppVersion`。核心流程确实依赖新增能力时，索引与包声明采用同一最低版本。

用冻结的 App 验收这套设计。第一份测试源先请求文本目录。第二份替换包改为官网授权、二进制目录和包内图片还原，并新增跟随界面语言的设置。两份包使用相同的作品和章节身份，第二份仍应在同一 App 上运行，已有设置与续读可保留。覆盖用户取消、授权撤销、错误重定向和旧宿主走回退路径。冻结的是 App 构建和协议，变化来自独立测试源及其受控站点。

## 取舍

设置语言可以在现有接口补一个可选字段。网络正文引用和交互续接复用现有导入及稳定的书源操作入口，按对应的能力标记启用。旧宿主仍可安装同一 WASM，因为这些扩展通过现有 JSON 信封传输。现有文本、网页验证、私有会话和图片处理已有消费者，沿现有入口增量整理。

参考 WASI HTTP 对状态、响应头和正文流的分离，以及 Extism 在宿主清单中限定插件可访问主机的做法。Koma 继续使用自身的 JSON 与 WAMR 入口，并复用当前包授权模型。[WASI HTTP 类型](https://github.com/WebAssembly/wasi-http/blob/main/wit/types.wit) · [Extism 插件清单](https://extism.org/docs/concepts/manifest/)
