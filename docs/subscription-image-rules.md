# 订阅图片规则实施设计

状态：用户已采用“通用处理器＋订阅级可复用规则”的方向。本文件是接入规划，尚未实现；下面的入口、默认值和协议字段为具体候选。

## 职责与首批范围

- App 提供通用的边缘特征匹配、裁剪、后台准备和派生缓存；规则提供识别特征、匹配顺序及适用的处理参数。App 不按站点名称、源 ID 或图片域名决定是否具备识别能力。
- 首批迁移现有顶部／底部横幅识别，包含旧版、新版、窄版和边缘叠加；保持已采用参考的采样、容差、匹配次序和缩放语义。图片中间插入、覆盖正文的水印不纳入这次裁剪算法。
- 通用规则用于正文图片，包括在线页、已下载页和本地漫画页；封面、缩略图及 App 界面资源不参与。
- 处理器留在 Koma 的图片准备适配层；共享 reader-kit 消费准备结果，不携带具体站点规则，也不为此增加另一个阅读器。

## 订阅协议与规则存储

保留现有数组式 `index.json` 和 `.koma` 包结构。在同目录的可选 `repo.json` 增加规则描述，现有 `meta.name` / `meta.website` 保持：

```json
{
  "meta": { "name": "订阅名称", "website": "https://example.org/project" },
  "imageRules": {
    "schemaVersion": 1,
    "path": "image-rules.json",
    "sha256": "<规则文件摘要>"
  }
}
```

- 路径沿用订阅目录下相对资源的解析方式；复用现有路径、大小、摘要和格式校验，不通过书源正文的 HTTP 会话获取规则。
- `image-rules.json` 使用版本化纯数据。首批检测类型拟为 `edge_signature_v1`：稳定规则 ID、规则版本、顶部／底部变体顺序、参考宽高、逐行 RGB 采样特征、宽度适配和容差。普通／叠加处理语义也由该规则描述。
- 发布端从原始模板生成采样特征；App 接收特征数据，无需内置模板品牌图像，也不执行规则脚本。算法类型版本归 App，具体特征版本归订阅。
- 新增规则 store 管理“订阅来源＋规则 ID＋内容版本”的完整快照。同一份内容按摘要复用；不同订阅即使使用相同文字 ID，也不能互相覆盖。
- 规则独立于源安装状态：添加订阅后可取得规则，不要求安装原站书源。规则标记的跨源适用性仅影响图片匹配，不改变原始图片请求、Cookie、来源权限或网络缓存归属。
- 规则是已取得的订阅资源。取消订阅停止后续同步，保留已取得规则，保持与保留已安装源一致；当前阅读任务持有自己的不可变快照。规则和选择随备份恢复，派生图片仍属于可清理缓存。

## 同步与首屏

- `SourceIndexMetadata` 解析可选描述；`SourceIndexService` 负责获取资源；`SourcePackageManagerCache` 已有后台检查与下拉刷新触发规则同步。不能只在订阅编辑页面读取，否则后台检查不会更新规则。
- 正常启动恢复本地已发布快照，后台同步；Reader 不等待订阅请求，不在翻页时拉取规则。
- 一份新规则全部验证和落盘后才原子发布。失败保留上一份有效版本，新增规则失败也不影响源安装列表或已有漫画内容。
- 添加、修改订阅地址时，旧来源记录和新规则来源一起按成功事务处理；只改自定义名称不下载规则。
- 阅读中固定本次规则快照，后台更新不重置可见图片。下次阅读使用新规则；用户主动改变当前漫画过滤选择时，才刷新对应派生结果。

## 控制形式候选

全局入口放在“设置 → 阅读”的现有图像分组，阅读器图像设置显示同名“横幅过滤”，复用现有选择行和菜单。

| 全局选项 | 行为 |
| --- | --- |
| 跟随书源（默认） | 保留现有源声明和用户选择；没有声明的正文不新增处理。 |
| 自动识别 | 对正文使用本地已取得、允许跨源使用的规则，按图片特征判断。 |
| 关闭 | 本范围不做横幅过滤。 |

阅读器中的单本选择增加“使用全局”，其余选择同上；单本显式选择优先于全局默认。它仅保存横幅策略，不复制整份 ReaderPreferences，也不混进只负责分页与方向的 SERIES_MODE_OVERRIDES_KEY。

“自动识别”是用户主动扩大处理范围，源是否声明处理不再是触发条件；选择“跟随书源”可恢复原来的源设置行为。普通／多重叠加由规则及源声明表达，第一批无需再给用户增加一组算法参数。

## 兼容现有源与发布顺序

- 现有 `imageProcessing.kind`、模式值及源设置通过规则中的兼容映射转换到通用计划；既有关闭、普通和强力选择继续有效。映射属于规则数据，不在 App 增加新的源 ID 分支。
- 默认“跟随书源”不能因为新规则尚未取得就让现有处理失效。先完成首版规则资源发布、旧模板到本地规则快照的兼容迁移和映射，再替换调用并移除旧身份／域名门控；兼容缓存不能在迁移完成前清除。
- 旧 App 忽略新增订阅字段，继续消费旧源输出。新 App 在同一页只执行一份有效过滤计划，不能旧服务和新规则各裁剪一次。
- 本项包含规则资源和 App 接入，不由此另发 App 版本或移动既有发布标签。规则发布沿现有书源库发布流程。

## 图片准备、预载与缓存

统一顺序为：取得原始正文 → 必需的源文字合成 → 横幅过滤 → 现有去白边／超分／翻译准备 → 显示。源文字先按原坐标合成，不能被当前 SourceTextOverlay 的提前返回绕开后续处理。

- 当前页和跨章预载共同进入同一个准备入口；检测、裁剪和编码在现有后台任务执行，进入可见区域前完成准备。第一版先复用现有检测语义，避免一边通用化一边更换识别算法。
- 原图缓存继续按原来的请求身份隔离。派生缓存身份包含原始内容摘要、规则快照摘要、算法版本和有效模式，不以路径或源名称代替图片内容。
- 有横幅／没有横幅的检测结果都保存，规则或原图变化才重新判断；同图同计划共用在途任务。沿用缓存所有者的容量统计和清理，不新建不受管理的派生目录。
- 开关或模式变化使相应准备计划失效，旧任务不能覆盖新结果；翻译、超分结果也必须使用新的输入身份，避免重复加载和旧处理结果回流。
- 图片边缘读取和长图内存占用作为性能验证项；先保持后台工作和已有并发边界，不宣称现有整图解码已变成零成本。

## 保存、导出与数据生命周期

- 下载文件、摘要和普通 CBZ 导出保留原始下载；已有源气泡必须合成的导出行为保持。
- 普通单图保存／分享消费阅读使用的过滤结果，关闭过滤后从同一原图重新准备，不回写下载文件。
- 漫画单本策略随书库备份；跨源复制／迁移作为这本漫画的显示选择继承，不搬旧源页面、下载或会话。删除漫画时清理该漫画策略。
- 已下载原图即使源被删除，也可用本地规则继续处理，不重新要求源运行、登录或在线解析图片地址。

## 实施顺序与验证对象

先做规则数据格式、发布资源、持久化及兼容映射；再接通普通正文、离线正文与预载；最后按采用的入口形式接 UI，并处理备份／迁移消费。

关键验证使用少量真实样本：原站图片、其他站点转载的同款图片、缩放／重压缩副本、无横幅正文、叠加横幅和本地／已下载页。确认裁剪后的第一行与最后一行正文、预载准备状态及原图字节不变；同时覆盖规则更新失败保留旧版、关闭后恢复原图、旧任务不能回流。既有包子默认与显式关闭路径必须保留，不靠新增大量源码匹配检查放行。

## 当前接线依据

- `SourceIndexMetadata.ets` / `SourceIndexService.ets`：现有订阅元数据只读名称和项目页，可加可选描述；`SourcePackageManagerCache.ets` 拥有后台索引检查。
- `SourceBaoziBannerService.ets` / `SourceBaoziBannerDetector.ets`：现有后台裁剪和签名匹配；`ReaderPageSourceAdapter.ets` 当前有源身份／域名门控。
- `KomaReaderLabAdapter.sourceFile/preload` 共用准备入口；`OfflineDownloadService` 保留原始字节；`ChapterArchiveExport` 普通图片保持原始文件。
- `ReaderPreferencesStore` 当前单本模式覆盖只有分页和方向；新策略必须保持该边界。
