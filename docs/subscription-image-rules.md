# 图片插件与订阅协议

图片插件是用户明确添加的外部资源，包含 WASM 算法、说明、配置与识别数据。App 提供运行时，不携带具体插件或默认订阅，不通过书源元数据发现图片处理内容。订阅与书源共用入口，由内容格式识别类型。工作进展及界面接入状态归 CURRENT_STATUS.md 原项。

## 插件目录与安装

插件目录使用 `schemaVersion: 2`、`kind: "image_plugins"`；其 `meta`、`revision`、`packs` 引用结构与下文数据式目录一致。每个引用指向一份插件清单，清单另引用带摘要的 WASM。算法接口、配置字段及输出合同见 [图片插件 ABI](image-processing-plugin-abi.md)。

添加或刷新订阅只取得目录与插件说明，不执行或安装新算法。显式安装校验并保存完整 WASM，新装插件默认关闭；安装更新保留原启停和设置。启用订阅的自动更新后，只更新已安装插件，不安装目录中新出现的插件。

新算法由独立 WASM 实现，通过订阅安装，不需要在 App 中新增算法类型。存储由现有 `ImageRuleStore` 持有，目录与已安装版本分开；刷新失败、坏包、安装失败保留原版本。卸载、移除或修改订阅后，迟到结果不能恢复旧插件。

## 管理入口

全局阅读设置和阅读器共用“图片插件”页，分别保留全局处理方式和当前漫画覆盖。页面按可更新／已安装／可安装分组；安装和更新为独立按钮，安装后默认关闭。点已安装插件使用公共半模态与设置字段编辑配置，保存动作在标题栏。订阅详情复用同一插件列表，不再维护第二份插件状态。页头进入已有订阅管理，下拉仅刷新目录。

## 类型与入口

- 书源订阅沿用数组式或含 `sources` 数组的 `index.json`，由 `SourceIndexService` 校验、保存和消费。既有订阅记录仍为书源类型。
- 数据式规则订阅使用 `kind: "image_rules"` 的对象式清单，由 `ImageRuleStore` 校验、保存和消费；可执行插件使用 `image_plugins`。
- 用户在同一个添加框输入地址并确认；App 下载清单后在后台解析类型，不让用户手选，不根据网址中是否含某个单词猜类型。
- 订阅页分别显示书源订阅与图片插件订阅。可查看名称、用途和版本，启停订阅、管理已安装插件，设置自动更新、手动刷新、编辑、复制地址、打开项目页及移除。
- 同一仓库可发布不同类型的清单。共用管理入口不要求共用一个地址，也不意味着添加一种订阅就自动添加另一种。

## 数据式规则兼容：清单与规则包

```json
{
  "schemaVersion": 1,
  "kind": "image_rules",
  "meta": {"name": "订阅名称", "description": "用途", "website": "https://example.org/project"},
  "revision": "清单内容版本",
  "packs": [{"id": "规则包标识", "version": 1, "path": "内容摘要.json", "sha256": "规则包SHA256"}]
}
```

规则包保留 `schemaVersion: 1`、稳定 `id`、正整数 `version`、可读的 `meta` 和 `rules`。每条规则提供稳定 `id`、`name`、`description`、处理器 `kind` 及该类型需要的数据。

首个处理器为 `edge_signature_v1`：签名包含参考宽高、逐行 RGB 特征及可选宽度缩放；`top`、`bottom` 指定边缘匹配次序；`crossSource` 允许自动识别；`legacy` 将书源的公开处理声明映射为单处／叠加模式。`sourceIds` 仅声明哪些旧缓存需要补查公开处理信息，不是识别资格限制，也不能触发订阅或下载。

App 校验清单类型、规则类型、尺寸、结构、资源摘要及包身份，完整下载和保存后才发布快照。此兼容格式只描述纯数据；新增算法使用 WASM 插件协议。同一订阅中，同 ID 的插件安装成功后替换对应数据式规则，不叠加执行；尚未安装替代插件时保留原规则及选择。

## 开发与发布

可执行插件在 `koma-sources/image-plugins/` 维护算法、声明、配置和数据，作者流程见该目录 README。数据式兼容规则仍由 `koma-sources/image-rules/` 的声明与模板生成，生成器不内置具体模板名称。

数据式规则和 WASM 插件分别发布到独立目录及固定 Release，均先上传内容寻址资源，再替换索引；不占书源的 latest，不移动 App 标签。插件生成器产出插件清单及算法 WASM，数据式生成器仅产出规则 JSON。用户明确添加对应 URL，不在书源 `repo.json` 中暗带处理订阅。

## 存储、更新与用户控制

- `ImageRuleStore` 拥有图片规则订阅、下载内容、启用状态和更新设置。存储文档为 schema 2；处理器只拿启用记录生成的不可变 `ImageRuleSnapshot`。
- 初始订阅和规则集合为空，不读 App rawfile。旧实现自动取得的 schema 1 快照不代表用户添加过订阅，不自动转换成启用订阅。
- 添加动作展示为图片插件订阅。名称默认从清单读取，用户可覆盖；只改名称不联网。
- 自动更新开关在订阅详情中可见。只检查用户已添加、已启用且允许自动更新的订阅，在 App 前台恢复时异步检查，每天至多一次；失败的检查同样保存时间，避免反复打开 App 时重复请求。手动刷新不受检查间隔限制。
- 更新失败保留原内容和选择；删除或编辑后迟到的请求不能恢复旧订阅。重命名、更新开关及后台刷新不重置当前阅读。
- 移除订阅同时停止消费其规则；用户主动启停、添加或移除使当前图片准备失效并按原阅读位置重新准备。后台更新固定当前阅读快照，下一次阅读使用新内容。
- 订阅内容及选择随备份保存。恢复保留显式订阅状态，失败回滚同一个规则文件。

## 阅读、缓存与文件关系

全局保留“跟随书源／自动识别／关闭”，单本额外提供“使用全局”。来源独立与应用策略是两回事：跟随书源只消费公开处理声明，自动识别按已启用规则匹配正文内容。

统一顺序为原始正文 → 必需的源文字合成 → 图片插件（兼容已有数据式规则） → 现有去白边／超分／翻译 → 显示。在线正文、已下载页、本地漫画与预载共用准备入口；封面和缩略图不参与。

原始缓存按既有请求身份隔离。派生和未命中缓存按原始内容、规则版本及模式区分，同图同计划共用任务。补查旧缓存声明失败时继续显示原图，不把请求失败保存为无处理或未命中；无缓存的新图片仍沿原请求错误流程。

原始下载、摘要和普通 CBZ 不回写处理结果；必需的源文字合成保持。普通单图保存和分享使用当前处理结果。漫画单本策略可复制／迁移，原书真正移出书库后才清理其选择。所有订阅与规则均不改变书源会话、Cookie 或图片请求权限。
