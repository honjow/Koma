# 图片插件与订阅协议

图片插件是用户明确添加的外部资源，包含 WASM 算法、说明、配置与识别数据。App 提供运行时，不携带具体插件或默认订阅，不通过书源元数据发现图片处理内容。订阅与书源共用入口，由内容格式识别类型。工作进展见[当前工作单](CURRENT_STATUS.md)。

## 插件目录与安装

插件目录使用 `schemaVersion: 2`、`kind: "image_plugins"`；其 `meta`、`revision`、`packs` 引用结构与下文数据式目录一致。每个引用指向一份插件清单，清单另引用带摘要的 WASM。算法接口、配置字段及输出合同见 [图片插件 ABI](image-processing-plugin-abi.md)。

添加或刷新订阅只取得目录与插件说明，不执行或安装新算法。显式安装校验并保存完整 WASM，新装插件默认关闭；安装更新保留原启停和设置。旧数据式规则也必须显式安装、开启；已有规则与停用选择随存储迁移保留。所有已安装内容仅通过管理页的更新操作替换。

新算法由独立 WASM 实现，通过订阅安装，不需要在 App 中新增算法类型。存储由现有 `ImageRuleStore` 持有，目录与已安装版本分开；刷新失败、坏包、安装失败保留原版本。卸载后迟到结果不能恢复插件。移除或修改订阅地址只改变目录来源，已安装内容保留原来源身份及最后已知名称，不自动转挂另一发布者。

## 管理入口

浏览中的书源管理通过顶部分段切换“书源／图片插件”；两类列表各自保留滚动位置，书源筛选与本地安装只出现在书源分段。图片插件复用全局阅读设置和阅读器的管理页与存储。全局顶部为“使用图片插件”总开关；阅读中默认“使用全局设置”，取消跟随后可单独启停当前漫画。总开关不修改各插件的启停与配置。页面按可更新／已安装／可安装分组；安装和更新为独立按钮，安装后默认关闭。点已安装插件使用公共半模态与设置字段编辑配置，保存动作在标题栏。订阅行菜单提供编辑订阅、复制地址、项目主页（清单提供时）及移除；插件安装、启停和配置统一在图片插件管理中进行。页头进入已有订阅管理，下拉仅刷新目录。

## 类型与入口

- 书源订阅沿用数组式或含 `sources` 数组的 `index.json`，由 `SourceIndexService` 校验、保存和消费。既有订阅记录仍为书源类型。
- 数据式规则订阅使用 `kind: "image_rules"` 的对象式清单，由 `ImageRuleStore` 校验、保存和消费；可执行插件使用 `image_plugins`。
- 用户在同一个添加框输入地址并确认；App 下载清单后在后台解析类型，不让用户手选，不根据网址中是否含某个单词猜类型。
- 订阅页分别显示书源订阅与图片插件订阅。可手动刷新、编辑、复制地址、打开项目页及移除。
- 同一仓库可发布不同类型的清单。共用管理入口不要求共用一个地址，也不意味着添加一种订阅就自动添加另一种。

## 数据式规则兼容：清单与规则包

```json
{
  "schemaVersion": 1,
  "kind": "image_rules",
  "meta": {"name": "订阅名称", "description": "用途", "website": "https://example.org/project"},
  "revision": "清单内容版本",
  "packs": [{"id": "规则包标识", "version": 1, "path": "内容摘要.json", "sha256": "规则包SHA256"}]
}
```

规则包保留 `schemaVersion: 1`、稳定 `id`、正整数 `version`、可读的 `meta` 和 `rules`。每条规则提供稳定 `id`、`name`、`description`、处理器 `kind` 及该类型需要的数据。

首个处理器为 `edge_signature_v1`：签名包含参考宽高、逐行 RGB 特征及可选宽度缩放；`top`、`bottom` 指定边缘匹配次序；`crossSource` 允许自动识别；`legacy` 将书源的公开处理声明映射为单处／叠加模式。`sourceIds` 仅声明哪些旧缓存需要补查公开处理信息，不是识别资格限制，也不能触发订阅或下载。

App 校验清单类型、规则类型、尺寸、结构、资源摘要及包身份，完整下载和保存后才发布快照。此兼容格式只描述纯数据；新增算法使用 WASM 插件协议。同一订阅中，同 ID 的插件安装成功后替换对应数据式规则，不叠加执行；尚未安装替代插件时保留原规则及选择。

## 开发与发布

可执行插件在 `koma-sources/image-rules/plugins/` 维护算法、声明、配置和数据，作者流程见该目录 README。数据式兼容规则仍由 `koma-sources/image-rules/` 的声明与模板生成，生成器不内置具体模板名称。

数据式规则和 WASM 插件分别发布到独立目录及固定 Release，均先上传内容寻址资源，再替换索引；不占书源的 latest，不移动 App 标签。插件生成器产出插件清单及算法 WASM，数据式生成器仅产出规则 JSON。用户明确添加对应 URL，不在书源 `repo.json` 中暗带处理订阅。

## 存储、更新与用户控制

- `ImageRuleStore` 在同一原子存储文档中分别维护订阅目录 `subscriptions` 和独立安装集合 `installations`，存储 schema 为 3。订阅只包含名称、地址、说明、项目链接、目录、更新时间及检查失败状态；已安装集合拥有算法字节、固定来源、启停和配置。
- 初始订阅和安装集合为空，不读 App rawfile。旧隐式快照不自动取得订阅权限。schema 2 显式订阅中的已有安装完整迁移；原订阅停用转换为该来源下各插件停用，原插件选择及配置保留。多个旧来源存在同名启用项时保留首个，其他安装记录保留并暂停，管理页说明来源冲突。
- 添加时自动识别订阅类型，名称默认从清单读取，用户可覆盖；只改名称不联网。刷新只更新目录；单地址失败保留有效目录、标记该地址，并继续检查其余地址。
- 图片插件沿书源的启动节奏做一次后台目录检查。启动与手动刷新共用进行中的请求。浏览 Tab 和书源管理按钮用角标显示书源与插件的合计，管理页分段在标签文字旁用独立角标分别显示各自数量，零项不显示数字。插件计数随目录和实际安装状态同步，只统计已安装且有可更新项的插件，兼容旧规则时一个规则包计一次。
- 没有订阅级执行开关或后台算法自动升级。目录中的新插件、旧格式规则和已装版本升级均由用户显式安装或更新；新装默认关闭。
- 已安装内容独立于订阅地址。停用或移除地址保留插件、配置、启停及来源；重新启用会检查目录。停用地址退出刷新、候选和下载，迟到请求不能提交。已识别为同一 GitHub 发行目录的代理自动承接更新，只在版本、清单及 WASM 摘要一致时尝试启用的备用地址。不同发布者的同 ID 插件保留原安装归属；更新保留执行顺序。下载地址身份及书源包回退见 [订阅身份](WASM_SOURCE_RUNTIME_DIRECTION.md#订阅身份)。
- 用户主动启停、安装、更新、配置或卸载使当前图片准备失效，并保留原阅读位置。目录刷新、重命名及移除订阅不会改变已装算法或重置阅读。
- 本地配置读取失败明确显示错误，禁止后续普通写入覆盖原文件；重试读取或显式备份恢复可恢复使用。算法执行失败保留可阅读图片，不写成未命中缓存，管理页可查看失败状态。
- 订阅、独立安装及配置随备份保存，恢复不重新下载算法；失败回滚同一个存储文件。阅读中顶部策略只影响当前漫画，下面的安装、启停、配置及卸载属于全局管理，界面明确标注。

## 阅读、缓存与文件关系

用户只控制是否使用图片插件及各插件的启停，不选择书源调用模式。已开启且声明 `application.automatic` 的插件可以独立处理正文；其余插件在 `sourceHints` 与已有公开声明匹配时参与。`context.application` 由宿主按这两条适用路径分别传入 `auto` 或 `source`，不再代表用户选择。通用插件不能为了处理缓存或本地图片而新增书源请求；只有依赖声明的旧缓存兼容路径可补查，失败不阻止其他独立插件。原持久值 `source` 与 `auto` 均按开启读取，`off` 保留；全局与单本覆盖、备份和插件配置不因模式合并丢失。

统一顺序为原始正文 → 必需的源文字合成 → 图片插件（兼容已有数据式规则） → 现有去白边／超分／翻译 → 显示。在线正文、已下载页、本地漫画与预载共用准备入口；封面和缩略图不参与。

原始缓存按既有请求身份隔离。派生和未命中缓存按原始内容、规则版本及模式区分，同图同计划共用任务。补查旧缓存声明失败时继续显示原图，不把请求失败保存为无处理或未命中；无缓存的新图片仍沿原请求错误流程。

原始下载、摘要和普通 CBZ 不回写处理结果；必需的源文字合成保持。普通单图保存和分享使用当前处理结果。漫画单本策略可复制／迁移，原书真正移出书库后才清理其选择。所有订阅与规则均不改变书源会话、Cookie 或图片请求权限。
